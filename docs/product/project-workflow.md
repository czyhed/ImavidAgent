更新日期：2026-10-21
状态：需求已定；服务端模板 / 实例（Issue #13）、工作流运行器（Issue #14）、精修三路径 / 交付候选（Issue #16）、质检审核与撤销（Issue #17）、打包导出 ZIP 与 manifest（Issue #18）已实现，前端画布、逐节点估价确认、精修与审核界面未开发。统一入口仍是 [功能规格与开发基线 v1.1](../FUNCTIONAL_SPEC.md)，本文是其 FLOW-13—FLOW-18 的专题细则；用户回答原文见 [确认记录 §05](../requirements/discussion-decisions.md#05-项目-ai-规划与工作流)。

## 1. 对象模型

```text
项目 project
 ├─ 资料快照 product_snapshot（02 确认时冻结）
 ├─ 方案版本 plan_version（v1、v2…，确认后不可改）
 │   ├─ 规划记录 planning_call（输入要求、模型、输出、用量与成本）
 │   └─ 交付项 deliverable（= 基线中的“交付项”）
 │       ├─ 交付项类型 task_type（库内类型或 ai_extension）
 │       └─ 工作流实例 workflow_instance（模板副本，记录来源模板及版本）
 │           ├─ 节点 node / 连线 edge
 │           └─ 运行 workflow_run（一次确认开跑；价格与输入快照）
 │               └─ 节点执行 node_run → 生成任务 job → 版本 deliverable_version
 ├─ 审核 review（只针对用户选定的交付候选）
 └─ 导出包 export
```

- 本文统一用“交付项”指方案中的一张计划图（界面也用此词），“生成任务”指 `sj_generation_jobs` 中的单次模型调用，见 [GLOSSARY.md](../../GLOSSARY.md)。一个交付项可有多个分支、多个版本，最终只有显式选定的候选进入审核。
- 工作流实例与模板脱钩：模板改版不影响已有实例；实例记录 `template_id + template_version`，用于追溯。
- 一个 `node_run` 若调用付费模型，仍落到现有任务契约（`queued → submitting → running → storing → succeeded / failed / unknown`），幂等、恢复和 23 小时改图保护线不变。

## 2. AI 规划（02 方案）

### 2.1 输入与输出

| 输入 | 说明 |
| --- | --- |
| 资料快照候选 | 当前已核实的商品/SKU 资料版本、已确认卖点、禁用表述、可用原图清单 |
| 补充要求 | 用户自然语言，如“突出防水，多做两张户外场景” |
| 交付项类型库 | 可用类型、各自默认画幅与默认模板 |
| 可用模型 | 已启用且可执行的图像模型；只用于推荐，不由规划自动付费试用 |

输出为 schema 校验后的交付项清单，每项含：交付项类型、标题、用途说明、数量/分支、提示词槽位（沿用基线 4.3 的九个槽位）、文案槽位、推荐画幅与模型、引用的商品事实、规划理由。

- 只允许引用资料快照中的事实；新增事实丢弃并标出“待核实建议”，不进入正式提示词（沿用 D15）。补充要求里的事实性描述（如“防水”）若不在商品资料中，同样标出，要求先更新商品资料。
- 规划结果是草稿，不自动确认、不建付费任务。用户可增删交付项、改类型和数量、重新规划；重新规划前提示会替换未确认的草稿清单。
- 文本模型不可用时回退为类型库的确定性默认清单（每类一项、模板默认提示词），不自动换另一个付费模型。
- 规划调用按 BILL-06 只记成本（`cost_only`），不预占。

### 2.2 交付项类型库

| 类型 | 用途 | 默认画幅 | 默认模板 |
| --- | --- | --- | --- |
| 白底主图 / 多角度 | 正面白底、侧面、背面等主图合规用途 | 1:1 | 提示词 → 生图 |
| 场景图 | 使用场景、氛围布景 | 1:1 或 3:4 | 提示词 → 生图 |
| 卖点 / 促销图 | 无字底图 + 模板合成文案 | 1:1 或 3:4 | 提示词 → 生图 → 模板合成 |
| 细节 / 尺寸 / 包装清单 | 细节特写、尺寸标注、包装内容物等信息图 | 1:1 或 3:4 | 提示词 → 生图 → 模板合成 |
| AI 扩展建议 | 类型库外、AI 针对该商品提议的图 | 1:1 | 提示词 → 生图（通用模板） |

画幅为汇总默认，可在交付项内修改；一期无目标平台输入，不按平台规格自动校验。类型库由管理员维护，本轮作为版本化配置随代码发布，后台编辑界面另行评估。

## 3. 工作流

### 3.1 节点

| 节点 | 输入 → 输出 | 计费 | 执行时机 |
| --- | --- | --- | --- |
| 商品资料（锁定） | — → 资料快照 | 无 | 01 |
| AI 规划 / 方案确认（锁定） | 资料 + 要求 → 交付项清单 | 文本只记成本 | 02 |
| 文本提示词 | 资料快照 + 交付项意图 → 结构化提示词槽位 + 文案槽位 | 只记成本 | 确认开跑前（W-12） |
| 生图 | 提示词 [+ 商品原图] → 图片版本 | 按图像价格预占/结算 | 开跑后 |
| 改图 | 源图版本 + 修改指令 → 图片版本 | 按图像价格预占/结算 | 开跑后 |
| 模板合成 | 底图版本 + 文案/Logo/品牌色 → `composite` 版本 | 不收生成费 | 开跑后 |
| 审核（锁定） | 各交付项的交付候选 → 已批准版本 | 无 | 05，人工 |
| 导出（锁定） | 已批准版本 → 导出包 | 无 | 06 |

- 节点参数：生图/改图可设模型、尺寸、质量、画幅；模板合成可选排版模板与文案。参数默认来自方案级设置，节点可覆盖（沿用 FLOW-07）。
- 端口有类型（资料、提示词、图片版本），连线时校验，不兼容拒绝连接。
- 改图节点只能接收同一供应商、能力兼容、源任务成功且未过保护线的图片；跨供应商改图不支持，连线或开跑前校验时明确报错。

### 3.2 结构规则

- 每个交付项的工作流是有向无环图；禁止回边与自环，保存时校验。
- 允许一个节点输出连到多个下游节点形成并行分支；每个出图分支独立建交付项、出版本。
- 锁定节点由系统生成，不可删除、断开或改顺序；交付项分组只能连到锁定的审核节点，不能直接连导出。
- 交付候选不由连线决定，由用户在交付项内显式选择（沿用 FLOW-09）。

### 3.3 模板与副本

- 管理员维护模板库：创建、修改（生成新模板版本）、停用；有实例引用的模板不硬删。
- 交付项创建时复制默认模板为实例；运营在实例内修改不影响模板。
- “另存为模板”默认保存为工作空间可选模板，并记录创建者；能否设为某交付项类型的默认模板仅管理员可操作。
- 停用的模型不能出现在新模板或新运行中；已运行实例保留模型快照。

## 4. 执行与费用

### 4.1 确认开跑

1. 用户确认方案（冻结资料快照、提示词、参数与价格版本）。
2. 系统逐节点估价：付费节点显示模型、单价、数量；未定价节点标“待核价”（BILL-03）；合计展示。
3. 用户一次确认开跑；系统在同一事务中按节点拆分预占（与基线 8.2 “一次确认开跑事务”一致），任一项明确拒绝时不遗留无主预占。
4. 节点按依赖自动串联，受单执行器和 10 个排队上限约束；并行分支在当前实现下实际串行排队。

### 4.2 失败、未知与修改

| 情况 | 处理 |
| --- | --- |
| 节点成功 | 结算该节点；产出版本可预览，可先进入精修（沿用 D12） |
| 节点明确失败 | 该分支停止，下游未执行节点释放预占；其他分支继续；不自动重试 |
| 节点 `unknown` | 下游保持等待，预占保留；只允许查询/恢复原请求 |
| 人工重试失败节点 | 新生成使用新幂等键，单独估价确认（沿用 FLOW-06） |
| 运行中修改工作流 | 已执行或执行中的节点锁定；未执行节点可修改，修改后释放原预占并重新估价确认 |
| 开跑后在交付项里新增手动精修 | 视为新节点运行，单独估价确认（沿用 FLOW-08） |

不允许“质检不过就重生”的自动循环；不自动换模型（D16、D-S-07）。

### 4.3 方案版本化

- 确认前：草稿清单可任意编辑与重新规划，只产生文本成本。
- 确认后：增删交付项、改类型、重新规划都生成新方案版本；已执行交付项、版本、费用记录保留，标注所属方案版本。
- 新版本中只有新增或改动的交付项需要确认开跑；未改动交付项沿用原实例与结果，不重复计费。
- “应用新版商品资料”沿用 FLOW-04：生成新资料快照，下游标需复核，不覆盖旧图。

## 5. 两种视图

| 项 | 六步视图 | 画布视图 |
| --- | --- | --- |
| 数据 | 同一项目、方案版本、交付项、运行和版本 | 同左 |
| 编辑 | 按步骤表单：资料、规划清单、交付项参数、精修、审核、导出 | 拖拽节点、连线、改节点参数、折叠交付项分组 |
| 状态 | 步骤状态由节点状态推算 | 节点显示状态色、费用徽标、产出缩略图 |
| 并发 | 两视图保存使用同一版本号乐观锁，冲突提示刷新 | 同左 |
| 手机 | 主要操作入口 | 只读浏览，不要求拖拽编辑 |

步骤推算规则：

| 步骤 | 依据 |
| --- | --- |
| 01 商品资料 | 商品资料节点预检通过 |
| 02 方案报价 | 当前方案版本已确认 |
| 03 制作任务 | 无图片输入的生图节点；全部结束（成功/失败/跳过，无排队、执行中或未解决 unknown）后完成 |
| 04 精修 | 带图片输入的改图节点、模板合成节点及开跑后的手动精修；批次结束且无进行中的精修才可进 05 |
| 05 质检审核 | 审核节点：所有交付候选已处理 |
| 06 打包导出 | 导出节点：导出包生成成功 |

当前步骤仍是最前面的未完成/需复核步骤（基线 4.1）。

## 6. 前端迁移（W-11、W-14）

- 现有 `prototype/prototype.html` + `generation.js` 是纯 HTML/JS；React Flow 依赖 React，因此前端整体迁移到 React。
- 顺序：① 在 React 中原样迁移五个菜单与现有真实生图、渠道管理、商品/评审演示，`tests/*-browser.mjs` 改写后通过；② 再开发工作流画布。迁移本身不扩功能。
- 构建与包管理：React、React Flow（npm 包 `@xyflow/react`）使用锁定版本；是否采用 TypeScript、构建工具选择在迁移开始时定，记录到本文。后端静态白名单改为服务构建产物，不开放目录浏览。
- 后端仍为 Node.js，框架未定。浏览器仍不得持有服务密码、供应商 Key 或长期 MinIO 密钥。

## 7. 依赖与风险

- **商品原图输入是保真前提。** 当前不能把商品原图传给模型（ACC-05 未通过，私有 CA 的 MinIO URL 不能直接交给模型）。在此之前，生图节点只能纯文生图，画面中的商品由模型生成，不是真实商品；工作流可先搭建和演示，但不能宣称产出“真实商品图”。
- 文本提示词与 AI 规划依赖 MODEL-06 `text.chat`；未接入前只能用确定性默认清单与模板提示词。
- 并行分支和多交付项受单执行器限制，开跑总时长会线性增长；不承诺固定耗时。
- 自定义工作流放大单次开跑费用，估价确认页必须清楚显示合计与待核价项。

## 8. 验收

见基线 ACC-18—ACC-22。自动测试使用模拟供应商与隔离数据，不产生真实付费任务。

## 9. 评审原型（2026-10-21）

`prototype/generation.js` 评审层已按本文更新，仍为浏览器本地演示（`sj:prototype:review:v1`），不调用模型、不扣费：

- 02：补充要求 → 确定性「AI 规划」（类型库 + 关键词，事实护栏提示未在资料中的说法）；交付项可增删、采纳 2 条扩展建议、选用已另存模板；确认后追加交付项生成方案 v2，已执行交付项锁定。

- 存储与安全：ZIP 写入私有桶 `shangjing-exports`，对象键为服务端生成，复用 `server/store.mjs` 的 MinIO 客户端工厂（TLS、项目 CA 与环境凭据），不硬编码账号密码。manifest、接口响应与审计均不包含桶名、对象键、内部 MinIO URL、连接串或密钥，只暴露逻辑文件名与下载接口。
- 幂等与费用：`POST /api/projects/:id/exports` 必须携带幂等键；服务先以 `building` 记录预约，同一键重复提交返回原记录且 `created=false`，不重新生成、不重复上传；同键但项目或方案版本不同返回 409。导出不创建生成任务、不预占、不写账本扣费，记录中的 `billing.amountCents` 固定为 0。
- 权限与审计：`GET /api/projects/:id/exports`、`GET /api/exports/:id`、`GET /api/exports/:id/download` 要求查看者；创建导出要求运营及以上，并校验工作空间归属。审计 `project.export.created / project.export.failed / project.export.downloaded` 只记录导出编号、项目、方案版本、文件数、缺项数与错误码，不记录对象键、桶名、内部地址或密钥。

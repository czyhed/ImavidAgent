## 1. 生产单位与对象链

**一个项目 = 一个商品 × 一个 SKU × 一次交付。**

```text
项目 project
 └─ 资料快照 product_snapshot（只读，含商品 ID 与资料版本）
 └─ 方案 plan（版本化；确认后冻结）
     └─ 批次 batch（方案的一次执行）
         └─ 资产 asset（白底 / 场景 / 卖点 / 视频行）
             └─ 生成任务 job（一次生成或改图，沿用现有任务契约）
                 └─ 资产版本 asset_version（v1、v2…；记录来源与模型）
 └─ 审核 review（针对"交付候选"版本）
 └─ 导出包 export
```

- 资产是"清单项"，不是文件；一个资产可以有多个版本，来自不同模型或不同改法。
- 批次只表示首次方案执行；之后的重试、换模型重生成、精修都属于该资产的新任务，不再回流批次。
- 视频资产一期只有"行"没有"任务"。

## 2. 状态机（三层，互不推断）

步骤状态不能由"当前第几步"推导，必须由业务事件写入。

### 2.1 项目状态

```text
草稿 → 进行中 → 待审核 → 已完成
          ↘ 已取消
```

- 进入"待审核"：批次已结束（无排队/生成中任务）、04 完成、没有进行中的改图任务。
- 进入"已完成"：导出包生成成功。
- 撤销通过或回退修改后，从"已完成/待审核"回到"进行中"。

### 2.2 步骤状态

`未开始 / 进行中 / 已完成 / 需复核 / 不适用`

- **需复核**：上游资料或方案变化，导致该步骤原有结论失效。旧资产保留，但标注所基于的版本。
- **不适用**：如未选视频时的视频相关步骤。
- "当前步骤" = 最靠前的未完成或需复核步骤，且**唯一**。
- 03 与 04 可以并行（D12）：只要批次还没结束，03 就是"进行中"，项目当前步骤停在 03；批次结束后当前步骤才前进到 04。

### 2.3 批次与资产

| 对象 | 状态 |
| --- | --- |
| 批次 | 排队中 / 生产中 / 部分成功 / 全部成功 / 全部失败 / 已取消 |
| 资产 | 待开始 / 排队中 / 生成中 / 已生成 / 失败 / 已跳过（未完成） |

### 2.4 任务

沿用现有契约，不新增状态：

```text
queued → submitting → running → storing → succeeded
                     ↘ failed
响应中断 / 状态不明 / 转存失败 / 进程重启 → unknown
```

## 3. 六步详表

| 步骤 | 输入 | 动作 | 门禁 | 产出 |
| --- | --- | --- | --- | --- |
| 01 商品资料 | 商品库中的商品与 SKU | 引用商品与 SKU；素材预检；禁用表述确认 | 至少 1 张可用主图；关键事实无冲突 | 预检通过的资料（尚未冻结） |
| 02 方案报价 | 资料 | **一键用文本模型生成成套提示词**；固定清单（白底 1 / 场景 2 / 卖点 2 / 视频可选）；每资产选模型（默认方案级）；实时报价 | 用户显式确认；**确认时同时冻结资料快照与每张提示词** | 方案快照（资料版本 + 资产清单 + 每张模型/提示词 + 单价） |
| 03 制作任务 | 方案快照 | 按资产拆任务，串行排队；失败资产可**生成改进建议**、重试或跳过 | 至少 1 个资产成功才可进 04；全部失败停在 03 | 资产 v1 |
| 04 精修 | 已生成资产 | 三条能力（见 §4）；自然语言改图指令转结构化提示词；每资产可换模型重生成 | 批次已结束（无排队/生成中）且无进行中的改图，才可进 05 | 资产 vN + 交付候选 |
| 05 质检审核 | 交付候选 | 自动检查 + 人工逐项处理；问题可生成修复建议 | 未处理问题不能"通过" | 已批准版本（冻结） |
| 06 打包导出 | 已批准版本 | 按 SKU 命名打包；manifest、生成标识 | 无批准版本不能下载 | ZIP / 单文件；项目完成 |

### 01/02 的资料冻结

- 01 只做引用与预检，改动随时可存；**冻结发生在 02 确认方案那一刻**。
- 冻结内容：商品 ID、资料版本、SKU、确认卖点、禁用表述、参考图清单。
- 商品库后续改版不自动影响项目；在 01 点"应用新版资料"会生成新的资料快照，并把 02 及其下游全部标为需复核。
- 已生成资产不会删除或覆盖，只标注"基于旧资料版本"。

### 03 的批次行为

- 一次方案 = 一批任务，受单执行器与 10 个排队上限约束。
- 每张成功即可预览、可先进入 04 精修，不必等整套（D12）。
- 排队中的任务可取消；在途取消需说明已发生费用。
- `unknown` 只能查询或恢复原任务，不能当失败直接重提。

### 05 的检查项

- 原图对照：仅对模型生成或整图润色的版本强制；模板合成版跳过商品保真，只查文字与排版。
- 文字：OCR 复核、溢出、禁用表述、规格一致性（规格来自资料快照）。
- 尺寸与画幅：对照渠道配置。
- 通过即冻结版本，记录操作者与时间。
- 撤销通过（D11）：必须填理由，版本解封回到 04 重新审核，不设返修次数上限；理由是审核记录的一部分，不进导出包。

## 4. 精修的三条能力

| 能力 | 作用对象 | 成本/耗时 | 风险与约束 |
| --- | --- | --- | --- |
| ① 模板重排 | 文案、Logo、品牌色 | 即时、≈0 | 确定性合成；版式受模板约束 |
| ② 底图二次优化 | **无字底图** | 付费、异步 | 商品可能漂移 → 进 05 强制原图对照 |
| ③ 整图润色 | 已合成的整张图 | 付费、异步 | 文字可能变形、商品可能变 → 必须重跑文字校验 |

推荐默认链路：

```text
底图（生成或整图改图） →〔可选〕② 模型优化 → ① 模板排版 → composite 版本
                                                   ↘〔可选〕③ 整图润色 → model_edit 版本
```

- 文字永远最后由模板合成，不经过模型；③ 是明确的高风险选项。
- 每个版本标记来源 `composite` / `model_edit`，并记录所用模型与参数。
- **交付候选必须显式选定**，不会自动取最新版。
- 换模型重生成（D8）产出的也是新版本，与既有版本并列，不覆盖。

## 5. 提示词与文本模型

### 5.1 四个入口

| 环节 | 触发 | 输入 | 输出 |
| --- | --- | --- | --- |
| 02 成套生成 | 一键 | 资料快照 + 模板槽位 + 创意方向 + 品牌语气 | 每个资产一条结构化提示词 + 文案建议 |
| 03 失败改进 | 单资产 | 原提示词 + 失败原因 + 资料快照 | 1–2 条改进建议，采纳后用于新任务 |
| 04 改图指令 | 单次改图 | 当前版本 + 自然语言要求 + 资料快照 | 结构化改图提示词（含"必须不变"约束） |
| 05 修复建议 | 单条质检问题 | 问题类型 + 当前版本 + 资料快照 | 改文字 / 重生成 / 换模型的建议与提示词 |

四个入口共用同一个提示词服务与同一套事实护栏，避免每个页面各写一套。

### 5.2 结构化提示词，而不是一段自由文本

模板定义槽位，文本模型只负责填值：

```text
主体与数量 / 场景 / 构图与视角 / 光线 / 风格 /
材质与颜色（来自资料）/ 必须保持不变 / 禁止出现 / 画幅
```

- 输出是可校验的结构，渲染成最终 prompt 时再拼接。
- 同一批资产共享"风格与约束"槽位，保证成套不漂移。
- 卖点文案是独立字段，走模板排版，不混进画面描述（与 §4 一致）。
- 模板槽位由运营维护；模型改的是值，不是结构。

### 5.3 事实护栏

- 提示词只能引用资料快照中已有的事实字段。
- 模型新写出的容量、材质、认证、承重等事实**默认丢弃并标红**，人工确认后才可写入。
- 禁用表述作为负向约束注入每一条提示词。
- "AI 建议卖点"与"页面上核实过的卖点"分开存，不自动升级为事实。
- 生成后做一次确定性比对（字段来源校验），不通过只作为建议展示。

### 5.4 智能，但不失控

- 默认路径只有 3 次点击：确认资料 → 一键生成方案 → 确认开跑。
- 所有 AI 建议默认是草稿，采纳才写入；提供原文与建议的对比。
- 不自动重试、不自动换模型（沿用既有边界）；要全自动必须另行授权预算。
- 文本模型不可用时回退模板默认提示词，不阻塞生成。
- 每张提示词、模型、尺寸、质量都可单独改；"全部采纳"只是批量操作，不是不可逆。

### 5.5 留痕

- 文本调用记录：模型、输入快照版本、耗时、token、费用。
- 任务冻结最终 prompt 全文与来源（模板 / AI / 人工混合）。
- 资产版本可回溯到当时使用的提示词、模型与资料版本。

## 6. 计费口径

| 时点 | 行为 |
| --- | --- |
| 02 确认方案 | 按方案内每个资产的单价预占总额 |
| 单个资产成功 | 该资产预占转已结算 |
| 换模型重生成 / 重试 | 新任务单独预占与结算；提交前显示预估费用 |
| 文本模型调用 | 只记录模型、token 与费用，计入项目成本明细；不预占、不单独结算（D17） |
| 失败 | 不结算；`unknown` 待供应商日志核对 |
| 导出 | 不计费 |
| 取消 | 在途取消说明已发生费用，按实际核对 |

## 7. 与其他议题的接口

- **商品**：本流程只消费 `product_id` + 资料版本快照；字段解析、持久化、多 SKU 归商品议题。
- **素材**：资产文件存储、命名、清理、导出包结构归素材议题；本流程只定义"哪个版本算已批准"。
- **系统**：渠道、模型目录、密钥、报价倍率归系统议题；本流程只消费"可用模型 + 单价"。
  需新增**文本模型**渠道类型（OpenAI 兼容 `/chat/completions`），可设默认文本模型，与图像/视频目录分开，密钥同样服务端托管。

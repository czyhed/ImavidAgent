## 1. 项目目标与当前状态

面向电商商家，提供从真实商品资料到成套商品图和短视频的制作、修改、审核与交付流程。

第一期建议主线：

**商品建档与核实 → 项目方案与费用确认 → 图片套图生产 → 精修 → 质检审核 → 打包导出。** 视频执行后续接入，本轮方案只展示未接入提示。

用户已经要求开展市场调研、汇总功能方案、制作 HTML 和功能思维导图，并将第一期功能保存为 Markdown，方便切换智能体继续工作。

当前已完成调研、规划、本地交互原型，以及首个真实生图接入。当前工作区保留第一期范围、功能思维导图和中间件接入文档；除下述已验证的生图链路外，本文的平台业务功能仍为待开发范围。

当前仅保留 [prototype/prototype.html](../../prototype/prototype.html) 一个页面入口。运行 `npm run dev` 后通过本机端口 4173 使用「项目 → 示例项目 → 03 制作任务 → 打开真实单图面板」：可选择接入的图像模型，提交文生图、查询任务、下载图片或基于成功版本继续改图。任务使用 PostgreSQL 持久化，成功图片保存到私有 MinIO；已用真实图片验证生成、转存、预览与下载。改图参数传递与源图校验通过自动测试，未额外进行付费改图验证。

2026-10-20 按四会话基线重新修改原型：主导航收敛为工作台 / 项目 / 商品 / 素材 / 系统，六步流程改为项目内横向导航（移动端两行）。新建项目、资料预检、模板方案与冻结、模拟批次、单项人工重试、未知原请求核对、版本和候选、逐项审核、撤销原因、部分交付 JSON 清单形成可操作评审链。工作台和账本共用本地演示数据；用户、登录、角色、调账、日志与价格仍为模拟。模型中心提供真实渠道管理的显式入口；演示方案不会自动提交真实任务，真实单图任务仍未关联项目。演示数据保存于 `sj:prototype:review:v1`。

素材页从现有接口读取真实成功任务，提供详情、下载、提示词复制和项目草稿引用；明确最近 50 个任务限制，尚未实现全量素材分页。模板页独立展示六个自制示意模板，变量填写后带入新项目，不自动生成。系统价格支持手动与 AI 查价候选的本地演示；查价未联网，示例金额不作为真实报价或结算依据。

商品原型已实现列表、手动录入、编辑、本地主图、浏览器保存、截图与预置链接建档演示。截图示例直接建待核实草稿，显示来源证据与置信度，重复示例复用已有记录；自选截图仅预览。用于创作进入项目草稿。录入方式与平台边界见 4.11；真实网页解析、视觉识别、商品数据库持久化与服务端项目引用尚未实现。

四个 OpenCode 会话已讨论生产流程、商品、素材与系统，核心范围已确认并汇总到开发基线；具体角色权限、视觉模型与上传限制、价格补算、保留期等仍保留待定项。用户已确定中间件采用 PostgreSQL、Redis、MinIO，并新增 OMYAI 作为首个生图供应商，要求支持后续扩展多能力模型；火山方舟保留为后续方向。本机接入使用 Node.js 后端与现有页面，不代表完整生产技术栈、首发品类、渠道或预算已确定。

测试中间件已于 2026-10-19 安装到用户提供的服务器 `203.0.113.10`（`203.0.113.11` 为同机另一个 IP），使用独立 Docker Compose 项目、公网 TLS 和独立强密码。版本、实际验证状态、凭据位置和接续操作见 [测试中间件接入文档](../infrastructure/test-middleware.md)。最初的 SSH 问题已定位为本机 Meta/Clash TUN 路径问题，通过物理网卡直连解决。后续智能体先读根目录 `AGENTS.md`。基础设施已就绪不代表业务功能已实现；火山方舟仍未接入。

## 2. 第一期间的交付范围

| 项目 | 当前建议 |
| --- | --- |
| 目标用户 | 中小电商商家及品牌；实际需求与付费意愿需访谈验证 |
| 商品范围 | 先选一个品类，以家居日用等结构简单、非透明的小件验证 |
| 生产单位 | 首轮原型先做单个商品、单个 SKU 的完整交付 |
| 商品入口与录入 | 左侧「商品」提供操作界面，三条录入路径：手动录入、链接解析（一期仅 1688 尽力解析）、截图识别（淘宝/天猫等）；解析或识别后一键建草稿再核实。作为可跨项目复用的商品资料库，详见 4.11 |
| 项目入口 | 先展示项目列表，再进入单个项目流程；列表至少包含状态、当前步骤、进度、费用和负责人，支持状态筛选与搜索 |
| 流程导航 | 桌面端使用左侧竖版步骤导航；完整流程为商品资料、方案报价、制作任务、精修、质检审核、打包导出，状态区分已完成、进行中、等待 |
| 工作台 | 汇总项目、产出、费用、任务状态、待办和渠道健康；指标口径与刷新频率待确认 |
| 模型渠道 | 管理图像和视频模型渠道、启用状态、默认模型及报价倍率；生成页只展示已启用且已连接的模型，可按任务切换 |
| 图片类型 | 白底图、场景图、卖点图，使用少量固定模板 |
| 视频类型 | 本轮仅目录/置灰方案行；真实视频、素材混剪与字幕合成后续接入 |
| AI 图生视频 | 后续验证供应商和商品保真后再开放，不纳入本轮执行验收 |
| 修改方式 | 改文字、换背景、圈选区域、替换单镜头、版本回退 |
| 交付方式 | JPG、PNG、MP4 和 ZIP 下载；由商家自行上传电商平台 |
| 规模限制 | 模板、画幅、生成数量和重试次数设上限；不承诺无限生成 |

完整调研方案曾建议以 3 类套图模板、2 类视频模板、2 种常用画幅控制首版范围；具体模板与尺寸尚未确定。

## 4. 功能清单与可观察的验收结果

下列编号沿用完整调研方案的 F01—F23，便于关联原始需求。为符合商家使用顺序，按七个功能模块重新归组。真实生图底层已按第 1 节接入，其余验收要求不因此自动视为已完成。

### 4.1 商品与品牌资料

| 编号 | 功能 | 解决的问题与具体能力 | 验收结果 |
| --- | --- | --- | --- |
| F02 | 商品档案与 SKU | 在独立「商品」界面手动录入资料，解析商品链接或识别商品页截图并一键建档；集中保存名称、参数、价格、参考图、SKU 变体、已确认卖点及来源，供项目复用，详见 4.11 | 手动和链接录入形成统一档案；缺失事实不编造，价格对应币种与规格，重复导入不静默覆盖；每个产物可追溯到商品、SKU 和资料版本 |
| F03 | 素材预检 | 在生成前发现错误格式、低清、尺寸不足、缺少角度或信息等风险 | 无效素材在付费生成前提示；用户知道应补什么资料 |
| F04 | 品牌设置 | 统一 Logo、品牌色、授权字体、文案语气和默认风格 | 同套素材使用指定品牌设置，品牌信息可以复用 |

### 4.2 智能创作助手

| 编号 | 功能 | 解决的问题与具体能力 | 验收结果 |
| --- | --- | --- | --- |
| F05 | 对话需求与结构化确认 | 将自然语言要求转为渠道、画幅、类型、数量、风格及预算明确的任务 | 用户可查看、修改并确认需求单，不能只有聊天记录 |
| F06 | 创意方向与制作计划 | 提供有限创意方向、营销文案和素材组合，帮助商家决定做什么 | 每项交付物、输入依赖与文案可确认；先确认再制作 |

前台呈现一个创作助手即可。内部可按需调用模型和工具，不要求商家选择多个智能体。研究阶段使用的 Claude Code、Codex、OpenCode 不等于未来平台必须集成这三个客户端。

### 4.3 商品图片制作

| 编号 | 功能 | 解决的问题与具体能力 | 验收结果 |
| --- | --- | --- | --- |
| F07 | 基础处理 | 抠图、白底或纯色背景、阴影、裁切、扩图和掩膜修正 | 主体完整，不改变商品颜色、结构和数量 |
| F08 | 商品场景图 | 围绕真实商品生成背景、布景和风格小样，减少场景拍摄工作 | 支持原图对比；细节变化可被标出并复核 |
| F09 | 主图与营销套图 | 用有限模板生产主图、卖点图、促销图；商品、文字、价格和 Logo 分层排版 | 同一商品可产出风格一致的套图；文字可直接修改，无需整图重生 |
| F10 | 局部修改与版本回退 | 对话修改、圈选区域、换背景，解决小改动导致整套重做的问题 | 修改产生新版本；批准版本保留且可回看、复用 |

第一期重点是白底图、场景图和卖点图。完整调研中的少量详情页模块可作为模板扩充项，是否纳入首个交付批次待确认，不扩展成完整详情页编辑器。

商品主图与营销卖点图需使用不同渠道规则，不能把带促销文字的海报直接用于所有平台主图。

### 4.4 商品短视频制作

| 编号 | 功能 | 解决的问题与具体能力 | 验收结果 |
| --- | --- | --- | --- |
| F11 | 脚本与分镜 | 根据商品事实规划 15 秒脚本、镜头时长、角度、素材来源、字幕和封面 | 用户可以预览和修改分镜，并在制作前确认内容与费用 |
| F12 | 视频生产与合成 | 默认用真实素材混剪、图文动画合成商品短片；保真测试通过后可加入模型短镜头 | 产出时长、画幅符合配置的可播放 MP4；未经验证的镜头不进入正式成品 |
| F13 | 配音与包装 | 基础配音、可编辑字幕、有限授权音乐及封面，减少手工包装 | 字幕清楚、音画同步、无明显溢出，声音和音乐授权范围可查 |
| F14 | 镜头修改 | 替换指定镜头、调整顺序或字幕，再合成新版本 | 不重新调用无关镜头的生成接口；其他已批准镜头保持可用 |

第一期不做完整专业剪辑器。缺少真实侧面、内部结构或使用演示时，应提示补素材或使用已有角度，不把推测画面当成真实商品细节。

### 4.5 质检与审核

| 编号 | 功能 | 解决的问题与具体能力 | 验收结果 |
| --- | --- | --- | --- |
| F18 | 基础质检 | 原图对比、文字识别、规格核查、尺寸及文字溢出检查、视频抽帧，提示商品或内容问题 | 展示问题与原因；Logo、结构、规格等关键问题进入人工复核，不以综合分数掩盖硬错误 |
| F19 | 审核确认 | 待审核、通过、驳回、理由和返修流程，区分预览结果与最终交付版本 | 商家明确批准最终素材；高风险结果不能无提示地成为已批准内容 |

自动检测提供辅助，不承诺零错误；检测漏报与误报需要通过真实商品样本单独评估。

### 4.6 素材管理与导出

| 编号 | 功能 | 解决的问题与具体能力 | 验收结果 |
| --- | --- | --- | --- |
| F20 | 素材与版本管理 | 按项目、商品保存原图、抠图、成品、脚本、分镜、修改历史与来源 | 从成品可找回上游输入和版本；长期素材不依赖供应商临时链接 |
| F21 | 导出与打包 | JPG、PNG、MP4、有限常用画幅、SKU 命名、ZIP 打包及可复制文案 | 文件可打开，名称与 SKU 对应，符合渠道配置并保留适用生成标识 |

### 4.7 平台基础支撑

| 编号 | 功能 | 解决的问题与具体能力 | 验收结果 |
| --- | --- | --- | --- |
| F01 | 登录与数据隔离 | 登录、工作空间、项目和基础角色，保护不同商家的任务与素材 | 商家之间不能互访素材、任务或下载地址 |
| F15 | 异步任务与进度 | 排队、阶段状态、通知、失败原因和恢复，解决长任务等待问题 | 关闭页面后任务仍继续；状态可查询，重复回调不重复入账 |

### 4.8 项目工作台与流程导航（跨模块交互）

项目工作台不是单独的生成能力，但决定用户从哪里开始、如何判断下一步。用户已提出「先看项目列表，再进入单个项目流程」的交互方向；下面把它转为第一期要求，其中列表字段、窄屏形态等细节仍需评审。本地原型已演示交互，业务数据、状态流转和权限仍待开发。

| 能力 | 第一期要求 | 验收结果 |

项目工作台是跨模块入口，不新增 F 编号，以保持 F01—F23 稳定；其数据依赖 F01 的工作空间与权限、F15 的任务状态、F17 的费用账本和 F20 的素材与版本管理。

工作台是登录后的总览页，不替代项目详情；指标以只读为主，异常项可以跳转到对应项目或系统页。指标口径必须与任务状态、费用账本和素材记录一致，不能各自计算。

| 能力 | 第一期要求 | 验收结果 |
| --- | --- | --- |
| 项目与任务 | 展示进行中、待审核、已交付和失败任务数量；失败任务说明原因与退款状态 | 数量与项目列表一致；失败不计入交付；点击可进入对应项目或筛选结果 |

| 待办与异常 | 集中展示质检问题、渠道延迟、额度阈值等需要处理的事项 | 每条有明确入口和责任人；处理完成后从待办移除或标记已处理 |

### 4.10 系统设置与模型渠道（跨模块配置）

系统页是底层配置入口，至少覆盖模型渠道、模型启用、默认模型、密钥与调用策略。生成页只展示已启用且已连接的模型，避免把不可用模型放进任务。

下表为完整目标要求；当前已实现 OMYAI 与 OpenAI 兼容渠道的新增、停用、删除、连接测试、模型目录自动发现、图像模型单张生成、本机默认选择与服务端加密托管。视频模型只同步目录，真实视频执行器、密钥轮换、精确报价和业务账本仍待开发。

| 能力 | 第一期要求 | 验收结果 |
| --- | --- | --- |
| 渠道管理 | 添加、编辑和停用模型渠道，填写名称、能力（图像/视频）、API 地址和密钥，并执行连接测试 | 渠道状态区分已连接、延迟偏高和待配置；测试结果有时间记录；停用渠道不参与新任务 |
| 模型目录 | 管理每个渠道下的模型、类型、用途、报价倍率和启用状态 | 停用模型立即从生成选择中消失；已完成版本不受影响 |
| 默认模型 | 配置主图像模型、主视频模型和失败回退策略 | 保存后对新任务生效，进行中的任务不切换模型；回退有明确记录 |
| 任务级选择 | 方案页可以选择本次任务的图像和视频模型，并显示报价倍率 | 选项只来自已启用且已连接的模型；切换后重新计算报价并在任务记录中留痕 |
| 凭据安全 | 密钥只在服务端加密保存，前端只显示掩码；支持测试和轮换 | 浏览器不持有长期密钥；密钥不出现在前端代码、页面 URL、日志或导出文件中 |
| 调用策略 | 配置并发上限、重试次数、超时、回调地址和 IP 白名单 | 与 F15 任务恢复、F17 费用账本、F22 商用基础一致；重复回调不重复扣费 |
| 当前边界 | OMYAI 与 OpenAI 兼容渠道已真实接入；系统页可新增 Base URL + API Key、测试连接并自动发现图像/视频模型；动态渠道密钥在服务端加密保存，前端只显示末四位掩码 | 仅图像模型可从「生图」执行；视频模型只进入目录，尚不能执行；没有完整业务账本、自动回退或多用户鉴权；渠道密钥文件丢失将无法解密已保存密钥 |

工作台和系统设置同样不新增 F 编号，以保持 F01—F23 稳定；权限依赖 F01，任务状态依赖 F15，费用依赖 F17，密钥与日志依赖 F22。模型供应商清单、渠道优先级和由谁维护密钥仍需确认。

### 4.11 商品管理与一键录入（F02/F03 的需求细化）

**用户已明确：** 点击左侧菜单「商品」要进入可操作的商品界面；可手动录入商品资料；可通过链接分析商品名字、参数、价格等信息，并一键录入商品。

**商品资料的定位（建议方案，待评审）：** 商品资料独立于生成项目维护，同一商品可供多个项目使用；一期先处理单个商品与单条来源，不扩展为整店采集或价格监控。当前可评审浏览器交互原型，不代表已经开发或验证了任何平台的真实解析能力。录入方式与平台边界已在本节下一小节定案。

#### 本轮评审结论（2026-10-20）

商品模块的录入方式与平台边界已经确定，后续开发按本节执行；与本节冲突的旧描述以本节为准。

- **录入方式确定为三条并列路径**：手动录入、链接解析、**截图识别**。截图识别是淘宝/天猫等无法抓取平台的主要录入方式，不是错误兜底页。
- **「一键」定义为**：一次操作完成解析或识别、字段填充并保存草稿，随后直接打开详情。**不采用**「先预览解析结果、再确认保存」的中间步骤。
- **建档门槛只有一个**：必须能确定商品名称。价格、参数、图片识别失败都不阻止建档；识别不到商品名称或页面不是商品页时**不建档**，明确提示原因并给手动录入与截图入口，不得生成空壳或编造名称。
- **平台边界**：仅 1688 承诺尽力真实解析，且以真实链接实测通过后才写进验收；淘宝/天猫**不做抓取**，统一走截图识别；其他平台不承诺解析，提供手动录入与截图识别入口。不承诺手机分享短链和需登录页面。
- **SKU**：数据模型按一个商品对应多个 SKU 建立，一期交互只允许录入或选择一个 SKU，二期开放多 SKU 时不迁移数据。
- **开发顺序**：先做不依赖样本的部分——① 商品表结构与手动录入/编辑/草稿与确认/资料版本；② 截图识别建档；③ 1688 链接解析适配器骨架与成功率探测脚本；④ 拿到真实链接实测后再决定是否写入验收。淘宝/天猫不写抓取代码。

#### 截图识别录入（淘宝/天猫等）

用截图代替抓取：用户在商品页截图，系统识别图中的标题、参数、价格、卖点并生成草稿。这属于用户主动提供的材料，不绕过登录、风控或访问限制。

| 能力 | 规则 |
| --- | --- |
| 多图合并 | 允许一次上传多张截图（主图页、参数页、价格页等），合并识别为一款商品；同一商品的重复上传不重复建档 |
| 字段证据 | 记录哪个字段来自哪张截图，截图本身作为来源证据保存到私有桶 `shangjing-assets`，表格只存对象键 |
| 置信度 | 名称、价格、规格等关键字段带识别置信度；金额、尺寸、型号等数值不允许静默采纳，低置信度标「待核实」并要求人工确认 |
| 不编造 | 截图中没有的字段留空；不按常见商品常识补齐参数、币种或规格 |
| 主图 | **不从截图裁切商品图作为生成输入**（清晰度与色彩不足）；主图需用户上传原图，截图仅作资料证据 |
| 隐私 | 截图中可能包含账号、订单等无关信息；上传前提示可裁剪，识别流程不把这些内容存为商品字段或写入日志 |
| 成本 | 识别消耗视觉模型调用，需在提交前说明本次消耗，并对同一批截图的重复提交去重计费 |
| 不支持的截图 | 模糊、信息不全、非商品页时返回部分成功或失败，保留已识别内容并提示需补哪一项，不建档空壳 |

**跨模块依赖**：截图识别需要接入支持图像输入的视觉理解模型。当前 `server/providers/openai.mjs` 只把模型分为 `image`、`video`、`other`，并过滤掉 `chat`、`vision` 等类型，**系统页尚无第三类模型能力**。因此「系统设置与模型渠道」（见 4.10）需新增视觉/文本理解能力类型、渠道配置与连接测试，由该会话确认；商品模块只依赖其提供的识别接口，不自行维护密钥。

#### 当前原型交付（2026-10-20）

- 保留 `prototype/prototype.html` 为唯一 HTML 入口，点击桌面左侧或手机底部「商品」进入列表与详情；支持名称/品牌/SKU 搜索和草稿、待核实、已确认筛选，预置四件明确标注的示例商品。
- 手动录入和编辑支持名称、品牌、品类、单一 SKU、价格/区间、币种、价格类型与条件、说明、卖点、自定义参数，以及一张本地主图（JPG/PNG/WebP，最大 4 MB，浏览器压缩）。保存草稿、核对确认、版本号及最近修改摘要可交互；未保存关闭时提示。
- 「链接录入」提供完整资料、缺少价格、需要登录三个预置示例；模拟解析进度后一次建档，成功结果标为待核实。重复示例链接打开已有记录，不覆盖修改；失败不建档，缺失价格留空。其他链接明确提示不支持真实解析。
- 「用于创作」仅对已确认资料开放，展示可复制的资料摘要和版本；不创建真实项目，不上传主图到模型，不提交付费生成。
- 商品与压缩主图保存在当前浏览器 `localStorage` 的 `sj:prototype:products:v1`。刷新同源页面可恢复，清除浏览器数据会丢失，不同步 PostgreSQL/MinIO，不支持跨设备或多人共享。历史摘要不等于完整版本快照。
- 已通过语法检查与独立浏览器流程验证：新增、编辑确认、版本变化、刷新恢复、搜索筛选、未保存放弃、正常/缺失/失败导入、重复链接、HTML 文本转义及手机端无横向溢出。测试不写后端数据或发起生图调用。
- 尚待实现：真实抓取与字段证据、截图识别入口、多 SKU、参考图/详情图管理、字段级来源和历史版本、服务端持久化、权限与项目引用；仍须按下文验收真实链接解析与截图识别能力。原型当前只有「手动新增」和「链接录入」两个入口，截图识别尚未做界面。

#### 页面与操作流程

- 「商品」入口：在现有应用内保留左侧导航和页面头部，右侧显示商品列表。顶部提供「手动新增」「链接录入」「截图录入」与搜索；无商品时展示三种录入入口。列表建议展示主图、名称、品牌或品类、SKU 摘要、价格/币种、资料状态、来源及更新时间。
- 手动新增：填写统一商品表单，支持增减参数行、上传参考图、保存草稿和继续编辑。建议名称为保存的最小必填项；价格、SKU 或图片缺失时可存草稿，不阻断录入，也不自动补出虚假值。
- 链接录入：粘贴一个商品详情链接，点击「解析并录入」。一期仅 1688 进入真实解析；淘宝/天猫及其他平台直接提示不支持抓取，并一键切换到截图录入。按钮点击后显示解析状态，重复点击不能创建多个相同商品。
- 截图录入：上传一张或多张商品页截图，系统识别并建档，成功后打开详情展示结果与待核实字段。适用于淘宝、天猫等无法抓取的平台，也可用于任何平台的快速录入。
- 「一键」定义：一次操作完成解析或识别、字段填充与草稿建档，随后打开详情。核实资料是后续使用环节，不要求用户确认每个字段后才能保存草稿。
- 商品详情：查看、修改资料与来源，标出缺失、冲突和待核实字段；建议提供「用于创作」，将所选商品及 SKU 带入项目或生图准备环节。该动作不直接启动付费生成。
- 保存与资料状态：建议区分「草稿」「待核实」「已确认」，资料确认不等于商品已上架或在售。重开页面后已保存内容仍可查询；离开有未保存修改的表单时提示保留或放弃。

#### 商品字段与解释规则

| 信息组 | 建议字段 | 录入与解析规则 |
| --- | --- | --- |
| 基础信息 | 商品名称、品牌、品类、商品描述、商家自定义编码 | 解析到的原始标题与用户修改后的名称可追溯；品牌和品类无法识别时留空，不按常识补齐 |
| 参数 | 颜色、材质、尺寸、重量、容量、型号，以及可扩展的「参数名 / 值 / 单位」列表 | 保留单位、范围与适用规格；参数应来自页面证据或人工输入，无法确定的标记待核实 |
| SKU 与规格 | 来源商品 ID、来源 SKU ID、商家 SKU、规格组合 | 区分整个商品和具体规格；多个规格不得混成一个 SKU；来源 SKU 与内部编码分开，不能伪造外部编号 |
| 价格 | 金额或价格区间、币种、价格类型、对应 SKU、适用条件、采集时间 | 区分售价、划线价、券后价、会员价和起价；无法确定币种或条件时标记待核实；未识别到价格应为空，不写成 0 |
| 图片与素材 | 主图、参考图、详情图候选、图片来源 | 建议解析时展示图片候选供选择，不默认整页下载；明确商品图与广告图的区别，记录用户确认的使用权限 |
| 创作信息 | 已确认卖点、禁用表述、补充说明 | 页面原文提取与 AI 改写建议分别保存；AI 推导的卖点不得自动变成商品事实 |
| 来源与核实 | 手动/链接来源、来源平台、输入链接、最终商品链接、采集时间、关键字段证据、修改与确认记录 | 标明哪些字段来自页面、人工修改或模型推断；保留旧值与来源，方便回看和纠正 |

价格是导入时的快照，不承诺实时同步；一个商品有多个规格或多个价格时，应保留对应关系或价格区间，不能擅自取最低价作为所有规格的售价。价格进入后续广告文案前需确认适用条件和时效。

#### 解析、异常与重复导入

| 场景 | 建议行为 | 验收要求 |
| --- | --- | --- |
| 可正常读取的商品页 | 自动提取支持的字段并建档，显示来源与采集时间 | 商品名称、参数、价格来自该商品；不能误取推荐商品、广告或页面导航内容 |
| 部分信息缺失 | 保留已提取内容并标记缺项；可以手动补录 | 无价格或图片也不丢弃有效资料；无法识别商品本身时不伪造名称和空白商品记录 |
| 多规格、多价格或信息冲突 | 展示可识别规格及候选值，提示用户核对目标 SKU | 不将不同规格的尺寸、颜色和价格混用；未确认事实不进入正式创作输入 |
| 无效链接、非商品页、失效页、不支持的平台 | 明确给出原因，保留用户输入，提供手动录入与截图录入入口 | 不显示“导入成功”，不创建看似完整的虚假商品 |
| 页面要求登录、验证码或无法读取 | 提示本次无法自动获取，直接引导使用截图录入或手动填写 | 不承诺全平台通用解析，不自动绕过访问限制；后续授权接入方式另行评估 |
| 截图清晰但信息不全 | 已识别内容入档并标记缺项，提示具体缺少哪项 | 不把截图外的常识补成参数或价格 |
| 截图模糊、非商品页或无法确定商品 | 返回失败或部分成功，不建档空壳，允许重新上传 | 不猜测名称，不生成看似完整的虚假商品 |
| 同一批截图重复上传 | 按图片指纹与工作空间去重，返回已有草稿或提示已存在 | 不重复建档，不重复消耗识别费用 |
| 短链接或跳转 | 在受支持且可安全访问的范围内解析跳转，保留最终来源 | 遇到无法解析或异常跳转时停止并提示；不能跳转后导入另一件商品而无说明 |
| 重复点击或重复链接 | 同一解析请求幂等；按当前工作空间、来源平台与商品 ID/SKU 或规范化链接识别疑似重复 | 相同请求只建一份草稿；已存在商品时提供打开已有记录或比较后更新，不静默覆盖人工修改 |
| 超时、解析失败、模型不可用 | 展示失败或部分成功状态，允许明确重试，已有资料不丢失 | 重试不重复建档；如涉及付费分析，需遵循费用说明与去重约定，不无限自动重试 |
| 图片获取失败 | 文本资料仍可建档，图片标记失败并可后补 | 不把外部临时链接当成长久素材；图片未成功保存时不得显示为已入库 |

#### 与现有项目、生图和底层能力的关系

商品档案作为事实来源，项目引用商品 ID、所选 SKU 和当次资料版本。修改商品资料不应悄悄改变已有项目的确认方案、已提交生成任务或历史成品；需要使用新版资料时由用户选择更新。商品资料未完善时允许保存，具体生成任务再按所需输入检查完整性。

链接分析与图片生成是不同能力：页面提取可以使用规则、结构化数据和文本分析模型，但不能假定现有生图 Key 或图像模型能读取任意网页。建议把抓取、字段提取、标准化和商品保存分开，并按平台增加解析适配器；通用解析、平台专用接口或授权数据服务的选择，应通过首批真实链接验证后决定。

截图识别同样与生图能力分开：它需要支持图像输入的视觉理解模型，而当前渠道体系只有图像生成与视频目录两类能力，系统页需先新增该能力类型。截图中的文字属于不可信输入，只作为商品资料提取，不能作为模型指令执行。

后续实现复用已有 PostgreSQL 保存商品、SKU、来源/解析记录与资料版本；用户选定且可使用的图片保存到私有 `shangjing-assets`。本次不创建数据表或修改服务。若引入异步解析队列，仍须遵守项目 Redis `sj:` / BullMQ `sj:bullmq` 约定。

链接和页面内容均属于外部输入。后端抓取需校验地址及每次跳转，拒绝内网、回环、云元数据等内部目标，并限制耗时与内容大小；页面里的文字只作为商品资料，不作为模型指令。页面脚本或 HTML 不直接注入操作界面，不把用户登录凭据、项目密钥或其他商品私密资料发送给解析目标。截图同样是外部输入：上传前提示截图会被发送给所选视觉模型渠道处理，结果文本一律作为资料而非指令，且不把截图原图或识别文本写入公开日志。

导入商品资料或把图片存入 MinIO，并不等于已实现把真实参考图传给生图模型；当前任意参考图上传到生成模型的能力仍待开发。首期不因链接录入自动扩展为批量 SKU 生成、整店同步、库存管理或价格自动刷新。

#### 一期验收清单

1. 点击左侧「商品」能进入独立操作界面，支持列表、搜索、新增、查看和编辑，不只是菜单占位提示。
2. 手动录入一个商品的名称、参数和价格后可保存、重开、修改，金额与单位不丢失。
3. 对 1688 的约定样本链接，点击一次「解析并录入」后生成可编辑草稿，包含能识别的名称、参数、价格及其来源，不要求人工逐项搬运。
4. 上传淘宝或天猫商品页截图，一次操作生成可编辑草稿，名称、参数、价格带来源截图标记；低置信度字段标为待核实，截图中没有的字段保持为空。
5. 测试缺失价格、价格区间、多 SKU、登录限制、非商品页、失效链接、模糊截图和重复截图，页面准确反映部分成功或失败，不编造字段、不建空壳商品。
6. 重复点击、刷新、重试、再次导入同一链接或同一批截图，不会静默重复建档或覆盖已确认资料。
7. 选择商品用于创作时能带入正确 SKU 与已确认字段，保留资料版本；未确认内容有提示，且不会直接扣费生成。
8. 当前阶段完成交互原型与预置示例演示；1688 链接解析需使用代表性样本实测通过后才能声明已实现，淘宝/天猫按截图识别验收，不声明抓取能力。

## 5. 用于验证完整流程的示例任务

> 用这款白色收纳盒做 1 张白底图、2 张家居场景图、2 张卖点图和 1 条 15 秒竖屏视频。只用我提供的容量数据，不改变结构和颜色。先给我看方案和报价。

验收这个例子时，至少检查：

- 工作台能看到项目、产出、费用、待办和渠道状态，关键数字能与项目列表及费用记录对上。
- 系统页能查看和添加模型渠道、启用或停用模型、设置默认模型；密钥只显示掩码。
- 方案页只展示已启用且已连接的模型，切换图像或视频模型后报价重新计算。
- 项目列表能看到白色收纳盒的状态、当前步骤与进度，能点入对应项目并返回列表。
- 仅在进入项目后展示六步生产流程；桌面端使用左侧竖版流程导航，窄屏下仍可切换步骤。
- 左侧「商品」可以手动建档、从 1688 约定样本链接一键录入，或上传淘宝/天猫商品页截图识别建档，获得名称、参数和价格；缺失或冲突信息可核实补全，随后把正确商品/SKU 的资料版本带入项目。
- 是否使用正确 SKU、颜色、结构、数量和已确认卖点。
- 图片是否成套、品牌风格是否一致，文字是否可独立修改。
- 视频是否可播放、时长正确、字幕清楚，商品信息是否准确。
- 能否仅替换背景或单个镜头，且保留其他已批准结果。
- 能否完成审核、打包下载和实际费用核对。

## 7. 后续工作顺序与待确认事项

建议按以下顺序继续，不要一开始并行开发所有模块：

1. 确定首发用户、一个优先品类、首批使用渠道和交付规格。
2. 收集授权商品样本，验证图片保真、视频路径与实际可交付成本。
3. 拆分页面和任务：先建立「商品」列表、手动录入与统一档案，再用约定平台样本验证单链接解析、一键建档和核实；随后接通商品资料到项目、图片修改和导出的最小流程，并固定竖版流程导航的步骤状态。
4. 接入模型渠道配置、默认模型与任务级模型选择，再接入分镜、15 秒视频合成、声音字幕与单镜头修改。
5. 完成预算账本、任务恢复、审核、隔离与标识后，再开展收费试点。

待确认事项：

- 首发客群是国内商家、跨境商家还是代运营团队？
- 首个品类和电商渠道是什么？商家通常需要哪几张图？
- 商品链接优先支持哪些平台？已定：一期仅 1688 尽力真实解析，淘宝/天猫走截图识别，其他平台给手动与截图入口；仍需用户提供 1688 代表性样本链接用于实测，并确认是否必须支持手机分享短链或需登录商品页。
- “一键录入”交互已定：解析或识别后自动保存草稿并打开详情，不设先预览再确认；核实作为后续环节。
- 商品录入的最小必填字段已定为商品名称加来源；仍需确认一期是否纳入商品主图上传与存储（建议纳入），以及多 SKU 是否确认留到二期。
- 截图识别使用哪个视觉理解模型渠道？该渠道由谁维护密钥，单次识别如何计价，是否需要限制单次上传张数与尺寸？
- 导入价格需要哪些类型和币种？遇到多规格、促销条件或重复商品时，默认如何展示和更新？
- 首版必须支持的画幅、分辨率和素材数量是什么？
- 少量详情页模块是否进入首个交付批次？
- 项目列表除状态与进度外，是否还需要按客户、渠道或负责人分组和排序？
- 进入项目时默认落在该项目当前步骤还是第一步？原型目前统一从第一步演示。
- 工作台需要哪些指标口径、刷新频率和统计时区？失败任务和重试如何计入？
- 首发接入哪些图像和视频模型渠道？默认模型、失败回退顺序和报价倍率由谁维护？
- 渠道和密钥由商家管理员、运营还是平台方维护？需要哪些操作审计？
- 团队人数、可投入时间和预算是多少？
- 是否已有可用的图片、视频和配音供应商账号及商用授权？
- 登录、收费、存储和部署方式有哪些既有约束？

以上问题不必一次全部询问；只在推进到相关工作且现有上下文无法判断时澄清。

## 0. 结论先行

用户的明确要求是：系统功能中要合并好**用户登录、新增用户、日志、账单**等管理能力，同时保留并衔接**已有模型渠道设置**。

本稿建议：

1. 登录是应用入口，不放在系统页签里；系统页只管登录之后的团队与费用管理。
2. 「系统」页由一个“模型渠道配置页”升级为五个标签：**用户与权限 / 账单与额度 / 日志 / 模型中心 / 安全与说明**。
3. 一期采用**单工作空间 + 三角色**（管理员、运营、查看者），所有业务数据带工作空间归属；多商家多租户预留字段，不在本期实现。
4. 账号由**管理员创建和重置**，不开放自助注册；首次启动创建第一个管理员。
5. 账单采用**平台内部额度账本**：管理员维护模型单价与倍率、手工充值/调账；供应商实际账单用于人工核对，不做在线支付和自动对账。
6. 日志合并为“操作审计 + 任务事件 + 计费流水”三类，统一筛选；密钥、密码、Cookie 等敏感值永不入日志。任务提示词全文可记入日志，但**仅管理员可见**。
7. 渠道设置继续使用现有 AES-256-GCM 加密和末四位掩码，扩展**价格、测试记录、权限和审计**；有历史任务的渠道由硬删除改为归档停用。
8. 计费默认开启；缺少价格的模型**仍允许执行**，任务标记“待核价”，事后由管理员补价结算。
9. 系统同时是**模型能力中心**：接入生图、生文、生视频、生语音等模型，按能力注册、标记、定价和设默认，供平台内其他智能体按需选择调用。

### 0.1 已确认决定（2026-10-20）

| 议题 | 决定 |
| --- | --- |
| 账号与租户 | 单工作空间多账号；一个部署服务一个商家团队，成员共享项目与素材，角色控制操作；多商家隔离后续再做 |
| 账单口径 | 内部额度账本；管理员维护单价、手工充值/调账/退款；供应商账单人工核对；不做在线支付 |
| 未定价任务 | 计费默认开启；未定价模型仍执行，标记待核价，不预占、不自动结算，补价后结算 |
| 日志内容 | 操作日志记录提示词全文，但仅管理员可见；普通成员只能看到任务编号、状态与费用 |
| 智能体范围 | 仅平台内部智能体；统一网关、内部身份与授权，不开放外部智能体调用 |
| 一期执行范围 | 生图保持真实执行；文本与视觉优先接入；语音、视频一期先登记目录，执行器后续 |
| 模型选择与回退 | 按“能力 + 别名/默认模型”调用，管理员可显式指定；不做自动付费回退，失败或状态未知只查询原任务 |
| 价格来源 | 录入模型可手动定价，也可 AI 查官方/渠道价；AI 结果必须管理员确认后才写入平台结算价 |
| 价格基准 | 官方标价与渠道价同时展示，平台结算价由管理员确定；官方价不直接等于供应商账单 |
| 价格档位 | 一期支持基础档位：文本输入/输出 token、图片尺寸/质量、视频按秒、语音按字符；完整阶梯价与缓存价后续 |
| 模型能力 | 系统是模型能力中心，接入生图、生文、生视频、生语音等模型；其他智能体按能力选择并调用，不直接持有供应商密钥 |

以上决定已同步到第 7、8 节和验收清单；第 15 节只保留尚未确认的事项。

## 1. 用户明确要求与本稿边界

### 1.1 已明确

- 系统功能要整合用户登录、新增用户、日志、账单等管理能力，不是四个互不相干的页面。
- 必须与现有模型渠道设置放在同一套系统功能里，不能另起一套互不相通的“设置”。
- 系统要能接入多种模型：生图、生文本、生视频、生语音等；其他智能体应能按能力选择模型并按需调用，不直接接触供应商密钥。
- 录入模型时要能直接指定价格；也可以让 AI 搜索该模型的官方价格，作为平台估价依据。
- 仍需遵守既有安全边界：浏览器不持有服务密码或长期 MinIO 密钥，渠道密钥只在服务端加密保存，前端只显示掩码。

### 1.2 已确认与本稿仍待确认

已确认（2026-10-20）：单工作空间多账号、内部额度账本、计费默认开启且未定价任务仍执行、日志提示词全文仅管理员可见；模型能力中心只服务平台内部智能体，一期保持生图并优先接入文本/视觉，语音/视频先登记目录，按“能力 + 别名/默认模型”调用且不自动回退；AI 查价结果须管理员确认，平台结算价由管理员确定，一期支持基础价格档位。详见 0.1。

仍待确认：

- 三个角色的具体权限边界（本稿矩阵为建议）。
- 账号是否只由管理员创建和重置，是否需要邀请链接或邮箱找回。
- 日志与提示词的保留期。
- AI 查价使用哪个搜索/浏览来源，官方页面允许清单、刷新频率与价格过期天数。
- 语音/视频首批供应商与未来真实执行时的计量方式。
- 视觉理解模型使用哪个渠道、如何计价、上传张数与尺寸上限。
- 未定价任务补价规则与供应商美元账单的汇率口径。
- 现有任务迁移方式，以及是否保留本机演示模式。

## 2. 现状与缺口

| 现状 | 缺口 |
| --- | --- |
| 服务绑定 `127.0.0.1`，`/api/session` 返回 `local-single-user` 和一个进程级 CSRF 令牌 | 没有账号、密码、会话、角色；所有接口无身份校验 |
| 系统页已有“渠道与模型 / 默认选择 / 连接说明”三个页签 | 没有用户、日志、账单入口；默认模型只存在当前浏览器 |
| 渠道密钥加密存 PostgreSQL，前端显示末四位 | 没有价格、测试时间/延迟持久化，没有操作审计 |
| 生图任务持久化 `sj_generation_jobs`，返回 `cost: null` | 任务没有用户/工作空间/渠道/价格快照；没有预占、结算或账单 |
| 任务只有当前状态字段 | 没有状态变更历史，无法回答“何时提交、何时成功、谁操作” |
| 渠道可直接删除 | 删除后历史任务和账目会失去渠道上下文 |
| 模型目录只区分 `image`、`video`，`chat`/`vision` 等类型被过滤 | 商品截图识别需要视觉理解模型；系统页缺少文本、视觉、语音等能力，无法登记、设默认或定价 |
| 模型目录仅存在内存，重启后重新发现 | 没有持久模型注册表；管理员的能力标记、启用状态、参数与别名无法稳定保存 |
| 只有生图任务入口 | 其他智能体没有统一的按能力调用入口；没有调用身份、限流、幂等、用量和审计 |
| 输出只把图片转存 `shangjing-assets` | 语音、视频、文本结果没有统一的存储、大小/时长限制、删除与导出策略 |
| 前端 `localStorage` 保存默认模型和商品原型数据 | 多人使用时默认值不一致；不能把登录态或密钥放进 `localStorage` |

## 3. 信息架构与页面结构

```text
登录页（未登录唯一可达页面）
└─ 登录：账号 / 密码 / 登录 / 联系管理员说明

应用外壳（登录后）
├─ 顶部：工作空间名、当前用户（显示名 · 角色）、修改密码、退出
└─ 系统页
   ├─ 概览条：成员数、本月已结算、当前预占、渠道异常、24 小时登录失败
   ├─ 用户与权限
   │  ├─ 成员列表：显示名、账号、角色、状态、最近登录、创建时间
   │  ├─ 新增用户：账号、显示名、角色、初始密码、首次登录改密
   │  └─ 行操作：停用/启用、重置密码、调整角色
   ├─ 账单与额度
   │  ├─ 指标：余额、预占、可用、本月已结算、月度预算使用率
   │  ├─ 流水：时间、类型、金额、余额、用户、任务、备注、操作者
   │  ├─ 操作：充值、调账、退款（仅管理员，必须填理由）
   │  └─ 价格表入口：按渠道 × 模型维护单价、单位、币种、倍率
   ├─ 日志
   │  ├─ 操作审计：登录、账号、渠道、计费、系统设置
   │  ├─ 任务事件：提交、运行、成功、失败、未知、取消、对账
   │  └─ 计费流水：与账单页同源，可从日志跳转
   ├─ 模型中心（原“渠道与模型”）
   │  ├─ 能力概览：图像生成、图像编辑、文本生成、视觉理解、视频生成、语音合成、语音识别
   │  ├─ 渠道列表：状态、最近测试、延迟、模型数、密钥掩码
   │  ├─ 模型注册表：能力、启用、参数范围、单价、倍率、最近校验
   │  ├─ 默认与别名：每个能力的默认模型、智能体可用的稳定别名、回退顺序
   │  ├─ 智能体访问：内部智能体、允许的能力与模型、额度与限流、调用密钥（如启用）
   │  ├─ 调用记录：智能体、能力、模型、用量、耗时、结果、费用
   │  └─ 操作：新增渠道、发现模型、标记能力、测试、启停、归档、密钥轮换（后续）
   └─ 安全与说明
      ├─ 会话策略、密码策略、登录失败限制
      ├─ 渠道加密密钥状态与备份提醒（不显示密钥）
      └─ 日志保留期、计费口径、供应商账单差异说明
```

设计约束：

- 系统页保留现有左侧导航和页面头部，不新开独立后台域名或第二套导航。
- 五个标签用现有 `sys-tabs` 样式扩展；窄屏下标签横向滚动，表格自身横向滚动，不挤压成卡片。
- 顶部概览数字必须来自与账单/日志同一数据源，不能像当前演示数据那样另算一套。
- 未登录时只显示登录视图；即使静态 HTML 可加载，所有业务 API 也返回 401，不靠前端隐藏。
- 所有破坏性操作（停用用户、归档渠道、调账）二次确认，并说明影响（例如“该用户现有会话将立即失效”）。

## 4. 登录与会话

### 4.1 首次启动

- 数据库没有任何用户时，只允许进入“创建管理员”引导页：账号、显示名、密码、确认密码。
- 创建成功后自动登录并写入审计日志 `user.created` / `auth.login.succeeded`。
- 引导接口在已有管理员后永久关闭，不能通过网络重复创建管理员。
- 现有任务、渠道和数据归入默认工作空间“商境工作空间”，`user_id` 记为系统/迁移占位，不删除。

### 4.2 登录

- 账号 + 密码登录，账号不区分大小写，显示名可重名，账号唯一。
- 密码使用 `scrypt`（Node 内置 `crypto`）加随机盐存储，不可逆；禁止明文、可逆加密或前端哈希。
- 登录失败一律返回“账号或密码不正确”，不透露账号是否存在。
- 连续失败限制：同一账号 + 来源 IP 5 次失败后锁定 15 分钟；使用 Redis `sj:auth:fail:*` 计数，键带 TTL，不存密码或密码摘要。
- 登录成功后可选择“保持登录”；一期建议默认会话闲置 12 小时过期、绝对 7 天过期。
- 首次登录或被管理员重置密码后，必须先修改密码才能进入业务页面。

### 4.3 会话与退出

- 会话令牌为 32 字节随机值，仅通过 `HttpOnly` Cookie 传递；数据库只存令牌摘要和 CSRF 摘要。
- Cookie：`HttpOnly`、`SameSite=Strict`、`Path=/`；通过 HTTPS 访问时加 `Secure`。本机 HTTP 开发不加 `Secure`，但 Host 白名单继续保留。
- 每个会话独立 CSRF 令牌，由 `GET /api/session` 下发；所有 POST/PATCH/DELETE 必须带 `X-CSRF-Token`。现有进程级全局令牌必须替换。
- 退出立即撤销当前会话；停用用户、重置密码时撤销该用户全部会话。
- 修改密码需验证旧密码，成功后撤销其他会话。
- 不使用 `localStorage`、URL 参数或日志保存会话令牌。

### 4.4 登录页元素

- 品牌名、账号、密码、登录按钮、错误提示。
- “忘记密码请联系管理员”说明，不提供邮件/短信自助找回。
- 管理员可在用户详情看到“最近登录时间/IP”，普通成员只看到自己的。

## 5. 用户管理与角色

### 5.1 用户字段

| 字段 | 说明 |
| --- | --- |
| 账号 | 登录标识，3–32 位字母/数字/下划线/短横线，工作空间内唯一 |
| 显示名 | 1–40 字符，用于日志、任务归属和账单 |
| 角色 | 管理员 / 运营 / 查看者 |
| 状态 | 启用 / 停用；停用后不能登录，现有会话失效 |
| 初始密码 | 管理员设置，至少 10 位；首次登录强制修改 |
| 最近登录 | 时间 + IP（仅管理员可见他人） |
| 创建/停用时间 | 用于审计 |

### 5.2 新增用户流程

1. 管理员在「用户与权限」点击“新增用户”。
2. 填写账号、显示名、角色，设置初始密码或生成一次性密码。
3. 服务端校验账号唯一、密码策略、角色合法。
4. 创建成功后显示一次初始密码，提示“关闭后不再显示”，并把“需修改密码”设为真。
5. 写入 `user.created` 审计，不记录密码。

补充规则：

- 不允许停用或删除最后一个启用的管理员；不允许管理员停用自己。
- 角色变更立即生效；若降级，下一次请求即按新角色鉴权。
- 一期不做“财务”独立角色；如需要，可在管理员基础上再拆，避免角色过多。
- 所有用户管理动作写审计，包含操作者、对象、变更前后角色/状态。

## 6. 数据归属与隔离

- 已确认一期为**单工作空间多账号**：一个部署服务一个商家团队，成员共享项目、商品和成品；任务和费用按用户归属，支持按人统计，但默认不做成员间互相隐藏。
- 所有业务表增加 `workspace_id`（或等价的归属键）；任务增加 `user_id`，成品通过任务归属。
- 若后续对外服务多个商家，必须补充多工作空间、成员表和跨空间隔离，不能只靠“一个部署一个空间”或账号前缀区分。字段一期先预留，避免届时重写表结构。
- API 鉴权顺序：会话有效 → 用户启用 → 工作空间成员 → 角色允许 → 对象归属匹配。跨空间对象统一返回 404，避免泄露存在性。
- 图片接口 `/api/jobs/:id/image` 必须校验登录和归属，不能只凭 UUID 访问；一期不提供无鉴权签名外链。
- 工作空间切换、邀请外部成员、成员级数据隔离不在本期，字段先预留。

## 7. 日志

### 7.1 三类日志

| 类型 | 来源 | 主要用途 | 是否可编辑/删除 |
| --- | --- | --- | --- |

| 计费流水 | `sj_billing_ledger` | 充值、预占、结算、释放、退款、调账 | 否，冲正用反向分录 |

日志页只做只读展示和筛选；计费流水在账单页也展示，但两者同源，不允许各算一套。

### 7.2 操作审计事件（建议清单）

### 7.3 字段与脱敏

建议字段：编号、时间、操作者账号与显示名、角色、动作、对象类型、对象编号、结果（成功/失败/拒绝）、来源 IP、请求编号、详情（变更前后值）。

脱敏红线：

- 密码、密码摘要、会话令牌、CSRF 令牌、API Key、渠道密文、加密主密钥、数据库连接串、MinIO 密钥永不写入日志。
- 渠道只记录名称、掩码、是否更换密钥；不记录密钥值或密文。
- 详情里的提示词按已确认口径记录**全文**，但只有管理员能通过日志接口和详情抽屉查看；运营、查看者只能看到任务编号、状态、模型与金额。日志导出默认不含提示词全文。文本模型的消息、视觉提取要求、语音合成脚本按同一规则处理。
- 截图识别的原始截图与识别文本不写入公开日志；商品模块按自己的证据字段保存，日志只记录“识别任务编号、模型、结果状态、耗时、费用”。
- 页面渲染日志详情时做文本转义，不把外部内容当 HTML 注入。

### 7.4 任务与调用事件

现有任务表只保存最新状态，建议增加 `sj_job_events`：任务编号、事件（queued/submitting/running/storing/succeeded/failed/unknown/cancelled/reconciled）、时间、操作者（系统或用户）、上游任务编号、耗时、错误码、费用相关占位。

要求：

- 每次状态变化追加一条，不覆盖历史。
- 上游重复回调只记录“重复回调被忽略”，不产生第二条结算。
- “未知/重启”必须显示原因和“查询原任务，不自动重新生成”的提示。
- 任务详情可从事件时间线看到从提交到结算的全过程。
- 文本、视觉、语音等同步调用只写 `sj_model_calls`；图片、视频、长音频识别等异步调用写 `sj_model_calls` 并关联 `sj_job_events`。

### 7.5 筛选、导出与保留

- 筛选：时间范围、日志类型、操作者、动作分组、结果、对象编号/关键字。
- 分页默认 50 条；默认倒序。
- 管理员可导出筛选结果为 CSV；导出动作本身写 `log.exported`，且导出内容不含敏感字段。
- 操作审计与任务事件建议保留 180 天；计费流水与结算记录不自动删除（数据量小，便于对账）。保留期可配置，但一期先固定。
- 不提供界面删除单条日志；数据库层也不授予应用删除权限以外的维护入口。

## 8. 账单与额度

### 8.1 口径

- 平台内部账本与实际供应商账单分开：内部账本用于给商家计价、预占和结算；供应商账单用于成本核对。
- 币种一期默认人民币（CNY），金额以“分”为整数存储，避免浮点误差。供应商按美元计价时，不在系统内自动换汇，由管理员在核价时确定平台单价。
- 价格来源一期为管理员维护的价格表（模型 × 操作 × 能力），单位支持“每张”“每秒”“每分钟”“每次调用”“每千 token”“每千字符”；文本可分别设置输入/输出 token 单价，倍率乘以基础单价。
- 供应商当前返回的价格为空，因此不能在未维护价格时假装知道成本。计费默认开启；缺少价格的任务按 8.5 节执行并标记待核价，不预占、不自动结算。

### 8.2 指标定义

| 指标 | 定义 |
| --- | --- |
| 余额 | 累计充值 + 退款 + 调账 − 已结算 |
| 预占 | 已提交但未结算/未释放任务的预估金额 |
| 可用 | 余额 − 预占 |
| 本月已结算 | 当月成功任务的实际结算合计 |
| 月度预算使用率 | （本月已结算 + 当前预占）/ 月度预算 |
| 待核价 | 有任务但缺少价格或需要人工确认的条目数 |

所有指标按工作空间汇总，同时可按用户、渠道、模型、时间筛选；工作台费用卡片必须调用同一汇总接口。

### 8.3 费用生命周期

```text
提交任务
  → 校验角色、模型启用、预算与可用额度
  → 有价格：写入预估金额与价格快照，记一笔 hold（预占）
  → 未定价：不预占，标记 fee_status=待核价，任务仍然执行
  → 任务执行
      ├─ 成功且有价格：settle（按实际张数/秒数/调用次数结算，多退少补）
      ├─ 成功但未定价：保持待核价，管理员补价后生成 settle
      ├─ 失败/取消：release（释放预占；不承诺供应商不收费）
      └─ 状态未知：保持预占，等待查询原任务或人工对账
  → 每次状态迁移使用幂等键，重复回调不重复扣费
```

关键规则：

- 幂等键建议：`job:<任务编号>:hold`、`:settle`、`:release`，数据库唯一约束；重复请求返回已有结果。
- 在途取消不自动退款；若供应商实际已扣费，由管理员以“调账/退款”分录处理并写理由。
- 未知状态不得自动重试或自动结算；对账成功后再 settle 或 release。
- 价格快照随任务保存，后续改价不影响历史订单。
- 结算金额与预占不一致时，差额用同一任务的分录调整，不修改旧分录。
- 任一余额变更在工作空间行上加锁或使用数据库事务，保证并发提交不超扣。
- 未定价任务不参与预算与可用额度校验，这是已确认口径的已知风险；管理员应尽快补价，或停用未定价模型。页面需在提交前明确提示“该模型未定价，本次仍会生成，费用待核价”。

### 8.4 流水类型

| 类型 | 方向 | 触发 | 备注 |
| --- | --- | --- | --- |
| 充值 | + | 管理员手工登记 | 线下转账/其他，填凭证号与备注 |
| 预占 hold | 冻结 | 任务提交 | 不改变余额，增加预占 |
| 结算 settle | − | 任务成功 | 释放对应预占并扣余额 |
| 释放 release | 解冻 | 任务失败/取消 | 仅释放预占，不产生收支 |
| 退款 refund | + | 管理员对任务退款 | 关联任务与理由 |
| 调账 adjust | ± | 管理员冲正/差异 | 必填原因，禁止直接改历史余额 |

一期不做在线支付、自动续费、发票/开票、优惠券和分账；这些不进入本期账本。

### 8.5 未定价与计费开关（已确认）

适用于生图、文本、视觉、语音等所有能力：

- 工作空间有“计费启用”开关，**默认开启**。这是已确认口径；不再提供“默认关闭”的推荐。
- 缺少价格的模型仍允许提交和执行：不预占、不结算，任务标记“待核价”，工作台与账单页显示待核价数量。
- 提交前必须明确提示“该模型未定价，本次仍会生成，费用待核价”；未定价任务不占用预算和可用额度，管理员需通过补价或停用模型控制风险。
- 管理员补价时，为任务确定结算金额并生成 settle 分录；补价动作写审计，记录定价依据。重复补价不重复扣费。
- 预算不足或可用额度不足时阻止提交，并说明还差多少；未定价任务不参与该判断。
- 价格变更写审计并记录生效时间；进行中的任务使用自己的快照；补价结算使用管理员补价时确认的金额，不追溯套用新价。

### 8.6 对账与报表

- 报表按时间、用户、智能体、渠道、模型、能力汇总调用次数、图片数、视频秒数、文本 token、语音字符/秒数和结算金额。
- 支持导出 CSV；导出写审计，不含密钥、连接串和提示词全文。
- 待核价任务单独列出，显示提交时间、用户、模型、用量与等待天数；补价后从待核价列表移除。
- 供应商月度账单与内部结算差异，由管理员按月生成一条“调账”分录，备注差异原因（汇率、折扣、四舍五入、供应商赠送等）。
- 一期不自动导入供应商账单；如需要，可作为后续适配器。

### 8.7 模型价格录入与 AI 查价

用户要求：新增/录入模型时可以指定价格，也可以让 AI 搜索该模型的官方价格，作为估价依据。

#### 8.7.1 先区分四种价格

| 价格层级 | 含义 | 用途 |
| --- | --- | --- |
| 官方标价 | 模型厂商官网公开价，可能按地区、税、企业协议、批量档位不同 | AI 查价的主要来源，作为参考 |
| 渠道价 | 当前接入渠道实际公布或结算的价格；聚合渠道可能加价、折扣或赠送 | 成本核对；平台定价时优先参考 |
| 平台结算价 | 系统内部账本对商家计价的价格，人民币分 | 预占、结算、报表的最终标准 |
| 供应商账单 | 供应商每月实际扣费 | 与内部结算价对账，差异走调账 |

已确认：**AI 查价负责找候选和来源，必须由管理员确认后才写入平台结算价**。官方标价、渠道价、平台结算价分开展示，由管理员确定结算基准；一期支持基础档位，不把不同档位压成一个数字。官方标价不等于渠道实际扣费，也不等于平台对商家的售价；不能把官网一个数字直接当成最终账单。

#### 8.7.2 两种录价方式

1. **手动定价**：录入或编辑模型时，直接填写能力、操作、单位、金额、币种、倍率和生效时间。可按能力批量设置，也可只改某个模型。
2. **AI 查价**：点击“AI 查价”，系统搜索厂商官网、官方定价页或当前渠道的定价页，返回候选价格列表：
   - 模型与操作（生图/文本输入/文本输出/视频/语音等）；
   - 档位条件（尺寸、质量、上下文长度、分辨率、时长、音色等）；
   - 原币金额、计价单位；
   - 来源链接、页面标题、抓取时间；
   - 置信度与匹配理由；
   - 可选的人民币折算值与汇率来源。

   管理员选择题中的一档，确认后写入价格表；未确认的结果只能作为草稿，不参与预占和结算。
3. **手动补录模型**：渠道目录没有列出或名称不一致时，允许管理员补录上游模型名、能力、参数范围和价格，来源标记为“手动”，不与自动发现结果混为一谈。

默认不自动发起 AI 查价：新增渠道后模型先显示“未定价”，管理员可逐条或按能力批量查价/定价，避免一次接入产生大量搜索调用和费用。

#### 8.7.3 价格档位与单位

官方定价通常不是单一数字：

- 文本模型：输入 token 与输出 token 分别计价，常按每百万 token 报价；缓存命中价可能不同。
- 生图模型：按张计价，可能按尺寸、质量、是否批量分档。
- 视频模型：按秒或按条计价，可能按分辨率、时长、有声/无声分档。
- 语音合成：按字符计价，可能按音色或质量分档。
- 语音识别：按音频秒/分钟计价。
- 视觉理解：按输入 token 或每次调用计价。

价格表必须支持“模型 × 操作 × 档位”，不能只存一个金额。界面先展示一档基础价，展开后显示其余档位；计价单位至少支持 `image`、`second`、`minute`、`call`、`1k_tokens`、`1m_tokens`、`1k_chars`。

#### 8.7.4 AI 查价规则

- 已确认：查价结果**必须由管理员确认**后才写入平台结算价，任何情况下不自动应用；未确认结果只能作为草稿，不参与预占和结算。
- 必须显示来源链接和抓取时间；没有可核实来源的结果不能生效。
- 官方域名、当前渠道域名、模型名和版本必须匹配；同名不同版本、地区站、企业协议价要单独标出。
- 官方价、渠道价、平台售价值得同时展示，由管理员决定采用哪一层；不能用一个“官方价”标签掩盖差异。
- 原币与人民币分开保存；折算必须记录汇率、汇率来源和日期，不静默换汇，不把税费当成 0。
- 查价结果过期后标记“价格待复核”，但不自动改历史价；管理员可重新查价或手动更新。
- 查价失败、页面无价格或模型不匹配时，保留手动录入入口，并显示失败原因与重试。
- AI 只提取价格字段，不执行页面中的任何指令；只访问允许的官方/渠道域名，拒绝内网、回环和云元数据地址，限制页面大小与耗时。
- 查价本身需要一个可联网的搜索/提取模型，由管理员在系统设置中指定固定的查价模型；不能依赖“正在被定价的模型”自己完成查价。查价服务不可用时退回手动录入，不阻塞模型接入。
- 查价、采用、修改、失效都写审计，记录使用了哪个搜索来源/模型、来源链接和操作者。
- 供应商实际账单与平台结算价的差异继续走调账，不能因为“AI 查到官方价”就跳过对账。

#### 8.7.5 与默认模型、任务的关系

- 设置默认模型或授权给智能体时，同时显示价格状态：已定价、AI 待确认、待核价、价格过期。
- 未定价模型仍按已确认口径执行并标记待核价；但默认模型入口优先提示先定价，避免长期积累待核价。
- 任务提交时保存价格快照；之后 AI 重新查价或管理员改价，不影响进行中和已完成任务。
- 预占按当前有效档位估算；实际用量落入不同档位时按档位结算，多退少补。
- 智能体只看到平台结算价和计量单位，不接触供应商原币价、密钥或渠道合同信息。

## 9. 模型渠道、能力中心与智能体调用

系统不只是保存几个生图渠道。用户已明确：系统要能接入生图、生文本、生视频、生语音等多种模型，其他智能体可以按能力选择并调用。因此模型中心由三部分组成：**渠道接入、模型能力注册表、统一调用网关**。

### 9.1 能力类型（可扩展）

能力使用稳定编号，不允许智能体用自由文本描述能力。新增能力必须同时定义输入输出、执行形态、计量单位和校验规则。

| 能力编号 | 名称 | 典型输入 → 输出 | 执行形态 | 计量单位 | 当前状态 |
| --- | --- | --- | --- | --- | --- |
| `image.generate` | 生图 | 提示词、参考图、尺寸、质量 → 图片 | 异步任务 | 每张 | OMYAI 与 OpenAI 兼容渠道已真实执行 |
| `image.edit` | 改图 | 原图/已成功任务 + 提示词或圈选 → 图片 | 异步任务 | 每张 | 当前基于供应商已成功任务，能力有限 |
| `text.chat` | 生文本 | 系统提示、消息、最大 token、温度 → 文本 | 同步 | 输入/输出千 token | 目录未接入 |
| `vision.analyze` | 视觉理解 | 一张或多张图片 + 提取要求 → 结构化文本 | 同步 | 千 token 或每次 | 目录未接入；商品截图识别依赖 |
| `video.generate` | 生视频 | 提示词/首帧、时长、画幅 → 视频 | 异步任务 | 每秒或每条 | 只同步目录，执行器未接入 |
| `audio.speech` | 语音合成 | 文本、音色、语速、格式 → 音频 | 同步或异步 | 每千字符 | 未接入 |
| `audio.transcribe` | 语音识别 | 音频、语言 → 文本/时间戳 | 异步任务 | 每秒或每分钟 | 未接入 |
| `embedding` | 向量化 | 文本 → 向量 | 同步 | 千 token | 一期可不做 |

“等等”意味着能力表可以扩展，例如图片理解、视频理解、音乐生成、数字人；但扩展必须走同一套注册、权限、计量和审计，不能为每个能力私接一条绕过网关的链路。

### 9.2 渠道与模型注册表

| 现有能力 | 整合方式 |
| --- | --- |
| 新增 OpenAI 兼容渠道、测试、发现模型 | 保留；测试结果落库（时间、状态、延迟），测试动作写审计并限频 |
| 启停渠道 | 保留；停用后不参与新任务，历史任务仍可查 |
| 删除渠道 | 改为“无引用才可硬删；有任务/价格/调用记录则归档停用”，列表默认隐藏归档项 |
| 密钥加密与末四位掩码 | 完全保留；日志只记掩码和是否轮换，绝不记录密钥 |
| 默认模型只存浏览器 | 迁移到服务端的能力默认模型和别名；仅允许已启用且已连接的模型；修改写审计 |
| 模型目录仅内存 | 新增持久注册表 `sj_models`，重启后保留能力标记、启用状态、参数范围和别名 |
| 模型能力类型 | 扩展到 9.1 的全部能力；目录同步不再丢弃 `chat`/`vision`/`audio` 模型 |
| 渠道健康 | 最近测试与调用失败汇总进入工作台“待办/渠道异常”，与日志同源 |
| 接口权限 | `/api/channels*`、价格、测试仅管理员；模型目录按智能体授权过滤；生图提交校验模型仍启用 |
| 模型录入与定价 | 发现模型后可逐个或批量定价；支持手动补录模型并定价；AI 查价结果确认后入库，规则见 8.7 |

商品截图识别是 `vision.analyze` 的跨模块依赖：商品模块只依赖系统配置的默认视觉模型或别名和服务端调用入口，不自行维护密钥、不选择未启用的模型。具体识别字段与置信度结构由商品会话定义；系统侧负责模型配置、计费口径、调用审计和错误分类。

注册表规则：

- 统一模型编号为 `渠道编号:上游模型名`，避免不同渠道同名模型互相覆盖。
- 目录同步只做新增和更新，**不自动删除、不自动停用**；上游消失的模型标记“目录已失效”，由管理员处理。
- 渠道返回的 `/models` 通常只有模型名，不能可靠判断能力。系统可做名称推断，但必须由管理员确认能力；**未确认能力的模型不进入智能体可选目录**。
- 一个模型可以声明多个操作（例如图像生成 + 图像编辑），但每个操作分别定价、分别记录用量。
- 每个模型保存可用参数范围：尺寸、质量、时长、音色、语言、最大 token、上下文窗口、输出格式。网关只接受范围内的参数。
- 适配器按协议拆分：OMYAI MCP（生图/改图）、OpenAI 兼容（对话、图像、语音合成、语音识别）、视频/语音专用适配器。协议差异留在适配器内部，不改变智能体看到的统一能力契约。
- 连接测试与能力测试分开：连接测试只读取目录；能力测试如需真实调用，必须由管理员确认可能产生费用，并记录结果与费用。
- 模型发现或手动补录时同步显示定价状态；可保存“未定价”，但设默认模型、授权智能体或提交调用前需提示。价格按模型 × 操作 × 档位维护，不把不同档位压成一个数字。

### 9.3 默认模型、别名与选择

- 每个工作空间按能力保存一个**默认模型**，例如默认生图模型、默认文本模型、默认视觉模型、默认语音模型。
- 提供稳定**别名**供智能体引用，例如 `image.default`、`image.cheap`、`text.fast`、`text.quality`、`vision.default`、`tts.zh`、`video.default`。别名映射到具体模型，管理员换模型时智能体代码无需修改。
- 选择优先级：智能体显式指定的模型（且在其授权范围内）→ 别名 → 该能力的默认模型。三者都不存在时返回 `MODEL_NOT_CONFIGURED`，**不随机挑一个模型**。
- 默认模型和别名修改后对新调用生效；进行中的任务使用提交时的模型快照，不中途切换。
- 设默认模型或授权给智能体时显示价格状态（已定价/AI 待确认/待核价/价格过期）；未定价仍可保存，但界面明确提示，且不自动补一个价格。
- 停用、归档、能力不匹配或最近连接失败的模型不进入可选目录。
- 一期默认**不做自动付费回退**（已确认）。如后续增加，只允许在上游尚未受理前回退，必须记录“为什么回退、从哪个模型到哪个模型”，不能把已提交或状态未知的任务换模型重跑。

### 9.4 智能体调用网关

所有智能体统一通过服务端网关调用模型，不直接访问供应商地址，也不接触密钥。

请求建议：

```json
{
  "capability": "text.chat",
  "model": "text.fast",
  "input": { "messages": [], "maxTokens": 800 },
  "idempotencyKey": "agent:product-copy:task-123"
}
```

- 入口统一为 `POST /api/model-gateway/invoke`；同步能力直接返回结果，异步能力返回调用编号，再通过查询或回调取结果。
- 一期只签**平台内部智能体身份**，使用服务端短令牌或内部身份，不开放公网外部调用；浏览器会话继续用 Cookie + CSRF，智能体令牌不依赖浏览器 Cookie。
- 网关先做鉴权、能力与模型授权、参数校验、价格与预算检查、幂等检查，再选择渠道并调用。
- 同步能力（文本、视觉、短语音）设置超时和最大输出限制；异步能力（图片、视频、长音频识别）进入队列，支持取消与状态查询。
- 每个调用记录调用方智能体、用户、能力、模型、渠道、参数摘要、用量、耗时、结果状态和费用；提示词全文仅管理员可见。
- 幂等键由调用方提供，同一智能体重复提交返回同一结果，不重复扣费。
- 禁止智能体传入任意上游地址、请求头或密钥；参考图只能来自受控存储或已校验的公网图片。
- 输出大小、时长、分辨率、字符数和并发数都有上限；超限在调用前拒绝。

### 9.5 调用策略与失败

- 按能力、渠道和智能体设置并发、速率和超时；限流键使用 `sj:model:*`，不占用登录限流键。
- 供应商错误映射为稳定错误码：参数错误、额度不足、内容拒绝、连接失败、上游不确定、结果存储失败等。
- 状态未知（超时、连接中断、服务重启）只能查询原任务，不自动重新生成、不自动换模型、不自动结算。
- 连续失败可在系统页标记渠道“异常”，但是否停用由管理员决定并留痕；不静默切换默认模型。
- 同一智能体的重复请求、回调重复到达、任务轮询重复触发，都以幂等键和状态机挡住。

### 9.6 用量、计费与内容存储

- 每次模型调用写一条统一调用记录，记录 `capability`、模型、智能体、用户、用量、价格快照、费用状态、耗时和错误。
- 计量方式按能力区分：图片按张，视频按秒，文本按输入/输出 token，语音合成按字符，语音识别按秒/分钟，视觉按 token 或次。
- 文本和语音等同步调用可先按最大 token/字符数预占，完成后按实际用量结算；未定价的调用仍执行并标记待核价。
- 图片、视频、音频结果转存私有 `shangjing-assets`，导出包进入 `shangjing-exports`；不把供应商临时 URL 当长期地址，也不向前端暴露 MinIO 长期密钥。
- 文本结果可保存在调用记录中；超过保留期或用户删除时，按素材删除流程处理，并保留必要的计费与审计摘要。
- 报表按能力、智能体、用户、渠道、模型汇总调用次数、用量和费用，工作台与账单使用同一汇总。

### 9.7 系统页呈现

- 「模型中心」顶部按能力显示卡片：默认模型、可用模型数、最近测试、今日/本月调用量、费用与异常数。
- 渠道列表保留现有新增、测试、启停、归档；展开后按能力分组显示模型。
- 模型行显示：能力、启用、参数范围、单价/单位、价格来源与状态（手动/AI 官方价/渠道价/待确认/过期）、最近校验、来源（自动发现/管理员标记）。
- 「默认与别名」支持为每个能力选默认模型、创建稳定别名、查看哪些智能体在使用。
- 「智能体访问」列出平台内部智能体，配置允许的能力与模型、每分钟限流、月度额度；一期不做外部智能体调用、公开密钥和开发者文档。
- 「调用记录」可按智能体、能力、模型、结果、时间筛选，详情显示用量、耗时、费用和脱敏参数。
- 新增渠道向导：填名称、Base URL、密钥 → 测试连接并读取目录 → 标记能力 → 手动定价或 AI 查价 → 选择默认模型 → 完成。未标记能力的模型不进入智能体目录。
- 未配置某能力默认模型时，相关智能体入口显示“请先在系统页配置某能力模型”，不自行挑模型。

### 9.8 分阶段落地（已确认）

一期目标：P0 + P1。语音和视频一期只登记目录，执行器后续接入。

| 阶段 | 能力 | 一期 | 说明 |
| --- | --- | --- | --- |
| P0 | 持久模型注册表、能力标记、服务端默认模型/别名、统一网关骨架、生图执行 | 是 | 先让现有生图和模型管理稳定，其他智能体通过网关调用生图 |
| P1 | 文本生成、视觉理解 | 是 | 支撑创作助手文案、商品截图识别；同步调用与 token 计费 |
| P2 | 语音合成、语音识别 | 目录 | 需要音色、格式、时长与字符计费；音频存储与试听 |
| P3 | 视频生成 | 目录 | 依赖具体供应商适配器、轮询、结果转存与按秒计费 |

所有阶段都从第一天按同一能力表登记目录；执行器未接入的能力显示“目录已同步，执行未接入”，智能体收到明确错误，不能自动改用其他模型或偷偷降级。当前代码只真实执行生图，文本、视觉、语音、视频均未实现，不能把本稿当成已上线能力。

密钥轮换、IP 白名单、并发上限等策略一旦加入，也必须走审计且不泄露密钥。

| POST | `/api/model-gateway/calls/:id/cancel` | 调用方或管理员 | 取消排队或可取消任务 |
| GET | `/api/model-calls` | 管理员；成员仅本人 | 调用记录筛选、分页、导出 |
| GET | `/api/audit-logs` | 管理员；运营仅本人 | 筛选、分页、导出 |
| GET | `/api/job-events` | 成员 | 按任务查询时间线 |
| PATCH | `/api/channels/:id` | 管理员 | 改名/改地址/轮换密钥（后续） |
| POST | `/api/channels/:id/test` | 管理员 | 连接测试，记录延迟 |
| DELETE | `/api/channels/:id` | 管理员 | 无引用硬删，否则归档 |

所有变更接口继续要求 CSRF；所有列表接口返回分页信息，避免一次拉全量日志。

### 10.3 迁移

- 建默认工作空间，把现有任务归入；现有渠道保留并补默认测试字段；不删除任何数据。
- 首次启动进入创建管理员引导；已有任务在账单页标记“历史任务/未计价”，不补造金额。
- 启动时把现有渠道的模型目录写入 `sj_models`，沿用当前图像/视频分类；文本、视觉、语音模型由管理员确认能力后启用。当前浏览器里的默认图像模型无法迁移，首次由管理员指定默认模型。
- 渠道加密主密钥继续使用 `.secrets/channel-encryption.key`；迁移前同时备份数据库与该文件。
- 现有浏览器测试需要先登录测试账号；静态原型仍可打开，但未登录只能看到登录视图。
- 不保留“免登录但可调用付费接口”的默认模式；如需演示，使用明确的只读演示模式或测试账号，且不能绕过鉴权。

## 11. 关键流程

### 11.1 首次启动

1. 检测无用户 → 显示创建管理员。
2. 校验密码策略 → 建用户、工作空间绑定 → 建会话。
3. 写 `user.created` 与登录成功审计。
4. 进入工作台；系统页显示成员 1 人、计费已启用但尚无价格、渠道沿用现有配置，待核价列表为空。

### 11.2 管理员新增运营

1. 填账号、显示名、角色、初始密码。
2. 建用户并标记首次改密。
3. 对方登录 → 强制改密 → 进入工作台。
4. 运营看不到用户管理、账单操作、渠道配置；尝试调用接口返回 403。

### 11.3 一次生图的费用

1. 运营提交任务：校验角色、模型启用与能力匹配；有价格时检查预算并预占，无价格时按待核价放行。
2. 有价格则记录价格快照与预估并写 hold；无价格则只写调用记录，不预占。
3. 成功：有价格按实际张数结算并写 settle；未定价保持待核价。失败：release；未知：保持 hold 并提示查询原任务。
4. 重复回调命中幂等键，不重复扣费。
5. 账单流水、调用记录、任务事件、操作审计可通过任务编号互相跳转。

### 11.4 智能体按能力调用

1. 智能体声明能力 `text.chat`、别名 `text.fast`，并带幂等键提交；不传供应商地址或密钥。
2. 网关校验智能体身份、授权能力/模型、参数范围、限流和预算；解析别名或默认模型。
3. 有价格则预占，无价格则标记待核价；写调用记录和幂等键后再调用供应商。
4. 同步能力直接返回文本；异步能力返回调用编号，由调用方轮询或接收回调。
5. 失败、超时或状态未知按错误码和原任务对账处理，不自动换模型重跑。
6. 调用记录显示智能体、能力、模型、用量、耗时和费用；提示词全文仅管理员可查。

### 11.5 管理员充值/调账

1. 选类型（充值/调账/退款）、金额、币种、备注；退款必须关联任务。
2. 服务端校验金额与权限，事务写流水并更新余额。
3. 写审计；页面刷新后余额与流水一致；重复提交不产生两条相同分录。

### 11.6 归档渠道

1. 管理员点击删除；系统检查是否有任务、价格或调用记录引用。
2. 有引用 → 提示改为归档，归档后不出现在新调用，历史记录仍保留渠道名快照。
3. 无引用 → 允许硬删，二次确认并写审计。

### 11.7 新增模型并定价

1. 新增渠道或发现模型后，模型默认显示“未定价”；可逐个或按能力批量定价。
2. 手动定价：选择能力、操作、档位、单位、金额、币种、倍率和生效时间，保存后进入有效价。
3. AI 查价：发起查价 → 查看候选档位、原币价、来源链接和抓取时间 → 管理员确认采用哪一档 → 写入价格表并审计。未确认结果只保存在查价记录中。
4. 查价失败或无可靠来源：保留手动定价入口，不自动补一个默认价格。
5. 设置默认模型或授权智能体时显示价格状态；新任务按当前有效价快照估价，历史任务不受影响。

## 12. 验收清单

1. 未登录访问时只看到登录页；登录后进入工作台；退出后刷新回到登录页。
2. 管理员能新增运营账号；运营首次登录被要求改密；改密后旧会话按规则失效。
3. 运营看不到用户管理、账单操作和渠道配置入口；直接调用对应接口返回 403。
4. 停用用户后其现有会话立即失效；不能停用最后一个管理员或自己。
5. 管理员充值、调账、退款后，余额、预占、可用和流水一致；重复提交不重复入账。
6. 计费默认开启；未定价模型仍可提交，提交前明确提示“费用待核价”，任务标记待核价且不预占；管理员补价后生成一次结算，重复补价不重复扣费。
7. 任务成功扣费、失败释放预占、重复回调不重复扣费；账单可从任务追溯到用户、渠道和模型。
8. 渠道新增/测试/启停/归档/改价都出现在审计日志；日志与导出中无密钥、密码、令牌或连接串。
9. 有历史引用的渠道不能硬删，归档后历史任务和账目仍显示原渠道名称。
10. 日志可按时间、操作者、类型、结果筛选；导出动作本身留痕；非管理员不能查看全量审计；日志中的提示词全文仅管理员可见，运营和查看者读取被拒绝，导出不含全文。
11. 首次启动能创建管理员；现有任务归入默认工作空间且不丢失；旧渠道继续可用。
12. 各能力的默认模型与别名改到服务端保存后，换浏览器登录仍一致；进行中的任务不切换模型。
13. 工作台费用卡片与账单汇总一致；渠道异常与测试记录一致。
14. 系统页可标记“视觉理解”模型并设置默认视觉模型；商品截图识别只能调用该模型，商品模块不接触密钥；识别用量进入账单；未配置时给出明确配置引导。
15. 同一渠道下可分别标记生图、文本、视觉、语音等模型；未确认能力的模型不出现在智能体目录；每个能力可设默认模型和稳定别名。
16. 智能体只能调用被授权的能力与模型，越权返回 403；重复幂等键只产生一次调用和一次费用；模型停用后新调用不可选，进行中任务不换模型。
17. 文本同步调用能返回内容；图片/视频异步调用返回调用编号并可查询；执行器未接入的能力明确返回“执行未接入”，不自动换模型。
18. 语音合成/识别结果可试听或下载，音频与视频转存私有桶；用量按字符、秒或分钟记录；不暴露供应商临时链接。
19. 调用记录可按智能体、能力、模型、结果筛选；用量与费用进入账单；提示词全文仅管理员可见，导出不含全文。
20. 新增模型可手动指定价格，保存后立即用于新任务的估价与预占；历史任务和已结算记录价格不变。
21. AI 查价返回至少一个可核实来源、抓取时间、档位与原币金额；未确认的结果不生效，无来源的结果不能应用。
22. 文本输入/输出 token、图片尺寸/质量、视频分辨率/时长等档位可分别保存；人民币折算记录汇率来源和日期，不静默换汇。
23. 官方域名与模型版本匹配时才可标记“官方价”；聚合渠道价与官方价同时展示，管理员能选择平台结算基准。
24. 查价失败时保留手动录入入口；网页内容不被当作指令执行；查价、采用、改价和失效都出现在审计日志。
25. 价格过期只标记待复核，不自动改历史价；重新查价或改价只影响新任务。

## 13. 一期不做

- 自助注册、邀请链接、邮箱/短信验证、邮件找回密码。
- 企业 SSO、OAuth、双因素认证。
- 多工作空间切换、跨商家租户管理、成员级项目隔离（字段预留）。
- 在线支付、自动充值、发票、优惠券、分账。
- 自动导入供应商账单、自动汇率换算、自动退款。
- 独立“财务”角色、复杂审批流。
- 操作日志外部不可篡改存储或 SIEM 对接；一期只保证应用层只追加。
- 模型训练、微调、模型上传、语音克隆、数字人、音乐生成等未列能力。
- 智能体直连供应商、自定义渠道脚本或任意上游地址；所有调用必须经过网关。
- 外部智能体公开接入、开发者文档和按调用结算；一期只服务平台内部智能体。
- 自动择优、竞价、跨供应商付费回退；默认不静默换模型。
- 无限流、无预算、无审计的模型调用。
- 自动绕过登录、验证码或企业协议去抓取非公开价格；AI 查价只读取公开可访问的官方/渠道定价页。
- 把 AI 查到的官方价直接当成供应商实际账单；差异仍需人工对账。

## 14. 与其他三个会话的接口约定

- **生图/视频会话**：任务提交前调用网关的预算与价格校验；任务表增加 `user_id/workspace_id/channel_id/model/price_snapshot`；返回预估费用；重复回调与重复提交共用幂等约定；取消/重试必须记录事件和费用状态。未定价任务返回 `feeStatus=待核价` 和提示，不阻止提交。视频执行器未接入前只登记目录，并返回明确错误。
- **商品/项目会话**：商品、项目、成品都带 `workspace_id` 与创建人；查看者只读；未确认商品资料不能直接触发付费生成；删除操作写审计。截图识别只调用系统配置的 `vision.analyze` 默认模型或别名，商品模块不持有密钥；调用用量写入 `sj_model_calls`，由系统统一计费。
- **创作助手/文案/脚本/配音等智能体**：统一调用 `/api/model-gateway/invoke`，按 `capability + 别名` 选择模型；不持有供应商密钥，不自行拼接上游地址。调用前接受能力授权、限流和额度检查；调用后以统一用量记录参与账单。
- **工作台会话**：费用卡片调用账单汇总接口，任务/渠道指标调用同一数据结构，不各自计算；按能力展示调用量、费用和异常；最近动态只展示脱敏后的审计或调用事件，不展示提示词全文。
- **公共约定**：PostgreSQL 表使用 `sj_` 前缀；Redis 键和频道使用 `sj:`，BullMQ 使用 `sj:bullmq`；能力编号、计量单位与错误码使用本稿定义，不在各模块私自定义；密钥和登录态不进 `localStorage`；不把密码、密钥、完整连接串写入日志、URL 或导出文件。

## 15. 待确认事项

1. **语音与视频**：语音一期只登记目录，先接语音合成还是合成 + 识别都要？首批供应商、按字符/秒/分钟计价、单次时长与文件大小上限是什么？
2. **查价来源与刷新**：AI 查价用哪个搜索/浏览来源或模型？官方页面允许清单、刷新频率、汇率来源和价格过期天数如何设定？
3. **账号来源**：仅管理员创建和重置，是否满足团队使用？是否需要邀请链接或邮箱找回？
4. **保留期**：操作审计/任务事件 180 天、计费流水长期保留，是否符合预期？文本、音频、视频结果保留多久，删除时是否保留计费与审计摘要？

7. **补价与汇率**：未定价任务补价时，按管理员确认的金额结算并记录理由，是否可接受？供应商按美元计价时，平台单价统一用人民币由管理员维护，是否可接受？

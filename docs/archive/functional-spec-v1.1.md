### 1.2 一期交付边界

**已确认的主线：**

1. 一个部署服务一个商家团队，单工作空间、多账号，共享商品、项目和成品，操作由角色约束。
2. 项目是唯一正式生产路径；现有生图工作台并入第 03/04 步。同一项目提供六步视图与 React Flow 画布视图，共用数据与审核/导出门禁。
3. 生产单位为一个商品、一个 SKU、一次交付；选定商品后由大模型在交付项类型库内规划套图（白底/多角度、场景、卖点/促销、细节/尺寸/包装，及 AI 扩展建议），每个交付项按可自定义工作流执行。
4. 商品提供手动、截图、1688 链接三种路径；淘宝/天猫不抓取，走截图识别。
5. 素材库收录全部真实成功产出，支持只读浏览和复用；预制模板与真实产出分开。
6. 系统整合用户、账单、日志、模型能力；平台内部智能体经统一网关调用模型。
7. 计费默认开启；内部额度账本与供应商成本分开，未定价任务可执行但须标明待核价。
8. 不自动付费重试、不自动换模型；状态未知只能恢复或核对原请求。
9. 模型录入支持手动价格与 AI 查价；官方价/渠道价分开展示，管理员确认平台结算价，基础档位纳入本轮。

**本轮不交付：** 视频/语音执行、批量多 SKU 生产、整店采集、淘宝/天猫抓取、库存/价格监控、素材完整管理、在线支付、外部智能体开放平台、多商家租户系统。

各讨论稿的“P0/P1”含义不同：系统稿的 P1 文本/视觉属于本轮；素材稿的 P1 收藏/隐藏等不属于本轮。统一用本文的“本轮 / 条件验收 / 后续”。

### 3.3 录入与确认

**手动：** 填名称及已知信息 → 保存草稿 → 补充/核实 → 确认资料。

**截图：** 上传多张同一商品截图 → 显示模型与费用口径 → 用户提交识别 → 提取字段及证据 → 能确定名称则直接建档 → 打开详情核实。没有可确定名称、非商品或混入多款无法归属时不建空壳，保留输入并说明问题。

**链接：** 校验平台/URL → 1688 尝试解析 → 成功则直接建档 → 核实。淘宝/天猫和不支持平台直接引导截图或手动；登录、验证码、手机短链等不承诺绕过或通用兼容。

- “一键录入”不增加解析后“再确认保存”中间页。**费用确认在模型调用前，资料核实在建档后**，两者不是同一次确认。
- 数值或规格冲突保留候选及证据，人工选择后再进入确认事实；缺价格不是价格 0。
- 截图只作为识别证据，生成必须另传清晰原图。上传前告知截图发往当前视觉模型，不提取账号、订单等无关信息。
- 去重按工作空间、请求 ID、来源商品/SKU 或规范化 URL、截图集合指纹执行。同一请求重复提交不重复识别/建档/计费；相似截图只提示疑似重复，不自动误合并商品。
- 商品确认与生产预检不同：资料不足仍可建档，进入项目 01 必须有可用原图且关键事实无冲突。
- **汇总约定：** 商品主图与证据随服务端商品模块存入私有 `shangjing-assets`，否则无法满足跨浏览器复用和项目引用。现有 localStorage 不自动覆盖服务端，迁移方式见 Q-06。

## 4. 项目六步生产

### 4.1 对象与状态

一个项目关联一个商品和一个 SKU，包含资料快照、版本化方案、首次执行批次、多个**交付项**、各项的版本/任务、审核记录和导出包。生产稿中的“资产”在本文统一叫“交付项”，素材库中的“素材”指实际文件，防止数据库概念混用。

```text
项目 → 方案版本 → 交付项（白底/场景/卖点）
                  ├─ 首次生成任务 → 版本 v1 → 素材文件
                  ├─ 精修/换模型任务 → 版本 v2 → 素材文件
                  └─ 显式选定交付候选 → 审核 → 导出包
```

- 项目：草稿 / 进行中 / 待审核 / 已完成 / 已取消。
- 步骤：未开始 / 进行中 / 已完成 / 需复核 / 不适用；由业务事件更新，不能只按序号推断。
- 批次：排队 / 生产 / 全部成功 / 部分成功 / 全部失败 / 已取消。
- 单任务沿用 `queued → submitting → running → storing → succeeded`，另有 `failed / unknown`；取消状态是待实现扩展，不能声称当前服务已支持。
- 当前步骤是最前面的未完成/需复核步骤。单张成功可进 04，但批次未结束时当前步骤仍停在 03。
- `unknown` 不等于失败；若存在未解决的未知任务，不可把批次视为已安全结束。部分交付需明确排除受影响项并留痕，未知费用仍待核对。

### 4.2 功能与验收门禁

| 编号 | 功能 | 行为与门禁 |
| --- | --- | --- |
| FLOW-01 | 项目列表 | 名称、商品/SKU、负责人、状态、费用、当前步骤；列表主进度为 4/6 步，资产进度在详情 |
| FLOW-02 | 01 商品资料 | 选择商品/SKU/资料版本，原图预检，核实卖点/禁用词；有可用主图且关键事实无冲突才进入正式生成准备 |
| FLOW-03 | 02 方案报价 | 由 FLOW-13 AI 规划生成任务清单、提示词、文案、模型与报价（不再固定白底/场景/卖点数量）；视频行标“执行未接入”，不建任务、不计入报价 |
| FLOW-04 | 资料与方案冻结 | 用户确认方案时同时冻结资料、提示词、参数与价格版本；应用新版资料须显式触发并标下游需复核 |
| FLOW-05 | 03 批次执行 | 一张一任务，受队列限额约束；成功即可预览；各项独立进度，不因一张失败重跑整套 |
| FLOW-06 | 人工重试与恢复 | 可保存重试参数预设，用户决定对失败项重试；新生成使用新幂等键；未知任务只查询原请求 |
| FLOW-07 | 模型与参数调整 | 方案级默认，每项可覆盖模型/尺寸/质量/画幅/提示词；生成后换模型产生新任务与版本，不覆盖旧图 |
| FLOW-08 | 04 精修三路径 | 模板重排、无字底图二次优化、整图润色；不同能力明示费用与风险；工作流内预置的改图/合成节点随整条工作流一次确认，开跑后新增的手动精修每次单独确认 |
| FLOW-09 | 候选与版本 | 新版本不自动成为交付候选；用户显式选定，保留源版本、模型、提示词、资料和模板来源 |
| FLOW-10 | 05 质检审核 | 事实/文字/尺寸/排版/商品保真检查，人工逐项处理；未处理问题不得通过；通过后冻结版本 |
| FLOW-11 | 06 打包导出 | 只导出审核通过的候选版本；JPG/PNG 原图与 ZIP、manifest；缺项明确列出，导出不收生成费用 |
| FLOW-12 | 文本智能辅助 | 02 AI 规划与成套提示词、03 失败建议、04 改图指令、05 修复建议；结构化输出、一键到待确认、保留手工调整 |
| FLOW-13 | AI 规划 | 输入资料快照与自然语言补充要求，在交付项类型库内选类型、定数量、写提示词；类型库外的“AI 扩展建议”需显式采纳；只引用资料事实；文本不可用回退类型库默认清单；只记成本 |
| FLOW-14 | 交付项类型库 | 白底主图/多角度、场景、卖点/促销、细节/尺寸/包装清单 + AI 扩展通用类型；各带默认画幅与默认工作流模板；版本化配置，管理员维护 |
| FLOW-15 | 工作流模板与副本 | 管理员维护版本化模板库；交付项复制模板为实例，运营可改参数、增删节点，只影响该交付项，可另存为模板；节点：文本提示词、生图/改图、模板合成 |
| FLOW-16 | 画布视图 | React Flow 项目总图；锁定商品资料/方案确认/审核/导出节点；交付项为可折叠分组；DAG、端口类型校验、并行分支各自成版本；与六步视图共用数据和乐观锁；手机只读 |
| FLOW-17 | 工作流确认与执行 | 逐节点估价、合计后一次确认并预占；节点自动串联；无循环、不自动重试；失败停该分支并释放下游预占；未知保留等待；未执行节点改动需重新确认 |
| FLOW-18 | 方案版本化与重新规划 | 确认前任意编辑和重新规划；确认后变更生成新方案版本，已执行交付项/版本/费用保留，仅新增或改动交付项需确认开跑 |

### 4.3 智能化与事实约束

默认操作目标是“确认资料 → 一键生成方案 → 确认开跑”，不是每个字段都反复弹窗。用户仍可逐项编辑、全部采纳或拒绝建议。批量采纳不会自动执行付费生成。

提示词槽位统一为：主体/数量、场景、构图/视角、光线、风格、材质/颜色、必须保持、禁止出现、画幅。批次共用风格约束，各交付项可覆盖。文案与画面描述分开，最终展示文案由模板排版。

02 生成方案时使用当前已核实资料的版本候选；**只有用户确认方案才冻结**。生成建议期间资料发生变化时，必须提示更新，不能用新资料解释旧提示词。

文本模型仅填槽位值；未在商品事实中出现的容量、材质、认证等不写入正式提示词，标出待核实建议。人工要采纳新事实时先更新商品并重新确认方案。禁用表述进入约束。模型不可用时回退确定性的模板默认文本，**不是自动换另一个付费模型**。

四个文本入口统一记录模型、输入版本、输出、用量与项目成本。**已确认：这些项目文本辅助仅记成本，不预占、不单独结算**，详见计费汇总规则。

### 4.3a AI 规划与自定义工作流（v1.1）

选定商品后，02 由文本模型结合资料快照与用户自然语言补充要求，在交付项类型库内规划交付项清单；每个交付项绑定一个工作流实例（模板副本），由文本提示词、生图/改图、模板合成节点组成，可并行分支出多个候选。规划和提示词节点在确认开跑前运行并随方案冻结；开跑时整条工作流一次估价确认，节点自动串联、无循环、不自动重试。六步视图与 React Flow 画布视图是同一项目数据的两种视图，画布中商品资料、方案确认、审核、导出为锁定节点。步骤推算、失败处理、模板权限和前端迁移顺序见 [project-workflow.md](product/project-workflow.md)。

**依赖：** 商品原图输入（ACC-05）未打通前，生图节点只能纯文生图，不能宣称产出真实商品图；AI 规划依赖 MODEL-06 `text.chat`，未接入时回退类型库默认清单。

### 4.4 精修、审核和交付

| 路径 | 输入/输出 | 检查 |
| --- | --- | --- |
| 模板重排 | 原始底图 + 文案/Logo/品牌色 → `composite` 版本 | 文字、规格、字体授权、溢出和画幅；继承底图的保真结论，未检查底图不能被模板“洗成通过” |
| 底图二次优化 | 无字底图 + 修改要求 → 新底图 → 模板合成 | 商品保真；模板文字按确定性规则检查 |
| 整图润色 | 已合成图 + 修改要求 → `model_edit` 版本 | 可能改变文字和商品，必须重新做保真与文字检查；不承诺文字永远不经过模型 |

- 复用供应商改图能力前先验证同供应商、模型能力、源任务成功与有效期；换供应商不能偷偷复用对方任务 ID。
- 原图、圈选、Mask、跨供应商改图不是当前已有能力。所需的**商品原图输入**为本轮生产闭环依赖，必须验证上传方式或公共信任读取地址后才能启用；不把私有 CA MinIO URL 直接交给模型。
- 返修：撤销通过须填原因，解除该版本的批准状态，回 04 后重新审核；不限制人工返修次数，但每次付费生成仍受预算和重试策略约束。
- 部分成功可交付的处理是生产稿的汇总方案：缺失交付项必须标记，导出不能冒充完整套图。全失败停在 03。
- 导出包建议按 SKU/交付项/版本命名；manifest 包含项目、方案/资料版本、交付项、候选版本、文件名/校验值、审核状态、缺项与生成说明，不含密钥、内部 URL、日志提示词或审核撤销理由。
- 普通素材下载不等于审核交付。未审核图可从素材库下载，但必须显示“未审核/非正式交付”；只有项目导出采用审核门禁。

### 5.2 收录和展示

- 生成任务 `succeeded` 且文件存储成功，才形成真实素材。失败/排队/未知/转存中是任务，不是产出。
- 每个成功生成或改图版本独立保留；同一回调不重复入库。多次真正成功的重生成分别计数，不能只保留“最后一张”。
- 项目模板合成后保存的真实成品也应归集为素材；这是六步全链路对素材模块的衔接约定。项目关联过滤可后置，但真实项目产出不能从“全部产出”遗漏。
- 截图证据、商品原图属于商品资料，不默认进入本轮真实产出页；后续上传素材另立范围。
- 新增成功数按素材创建时间统计，历史回填保留原始创建时间；本月按 `Asia/Shanghai`，不把回填时间当生产时间。
- 总数、文件可用数、占用空间分别定义；文件丢失不能悄悄从记录消失。模板示意图不计入产出和账单。
- 本轮没有收藏/标签编辑/隐藏/删除/素材批量 ZIP；与项目的正式交付 ZIP 是两种能力。

### 5.3 模板与复用

模板是提示词结构、示例图、适用范围、占位符、推荐参数与版本。默认建议约 10 个，可按可用能力裁剪；数量是汇总建议，不是已确认硬指标。

示例图采用项目自制示意图，清楚标“示意图 · 非真实生成”，不为此付费生成。示例图只能浏览/参考/下载，不冒充用户商品原图，也不自动上传给模型。

卖点/促销模板输出独立的底图提示词与文案槽位，接项目的确定性文字合成。视频分镜模板可以查看/复制结构，但不提交视频任务。推荐参数不兼容时提示选择，不能静默强行发送。

OMYAI 当前适配器按**23 小时**保守阈值限制改图（供应商图保留约 24 小时）。其他供应商以后按适配器能力返回有效期，不全局硬编码 24 小时。改图能力、来源和到期由后端判定。

- 连接测试只读目录；真实能力测试可能计费，必须说明并确认，测试调用同样入账和审计。

- 同一幂等键、相同请求返回原结果；相同键不同参数返回冲突，不能只按键吞掉新参数。
- 图像、音视频文件入私有桶，文本/视觉结果按业务证据和调用记录分开。计量保留原始 token/次数/张数，不能用“调用成功”伪造用量。
- 文本是否流式输出见 Q-03；本轮可先同步生成建议，不把流式 UI 当必须上线条件。

### 8.2 一套费用状态与事实来源

| 情况 | 内部处理 | 不应发生 |
| --- | --- | --- |
| 有价格的图像任务提交 | 原子创建任务、价格快照和预占；余额/预算不足拒绝 | 先调供应商后发现没额度；项目与单图双重预占 |
| 成功 | 一次结算并释放相应预占 | 因审核、导出、选择新候选重复收费 |
| 明确失败/排队取消且未受理 | 释放预占，不按成功结算 | 承诺供应商一定没收费 |
| 在途取消/上游未知 | 保留待核对状态；明确供应商结果后处理结算/释放 | 点击取消就承诺退款或重生成 |
| 未定价 | 提示待核价，仍执行，不占预算/可用额度；成功后人工补价 | 把未知费用显示为 ¥0 或静默套用最新价格 |
| 项目文本辅助 | `cost_only` 成本记录；费用不明可待核成本，不扣客户余额 | 按通用 token 规则再次预占/扣费 |
| 调账/退款 | 追加关联分录和审计，幂等 | 覆盖原流水、无理由手改余额 |

“确认方案时预占”与“任务提交时预占”合并为**一次确认开跑事务**：按交付项拆分预占，只记一次；任一项明确拒绝时不得遗留无主预占。后续精修/重试是新任务，单独报价确认。同一交付项多个成功版本分别对应真实生成成本。

用户明确选择了项目文本“记录成本，不预占”，系统稿泛化的“所有文本预占结算”不得覆盖这一具体决定。采用可配置 `billing_mode=chargeable/cost_only`：项目四类文本辅助固定 `cost_only`，截图视觉按常规计费。其他独立文本业务尚未定义，不在本轮另做收费入口。

平台金额、供应商成本、计量单位分列；默认建议平台 CNY、最终流水用分的整数。token 单价可能小于一分，应使用高精度定价/微单位计算，再按明确规则四舍五入结算，不能把所有 token 单价直接截成整数分。汇率、补价及余额不足后的处理见 Q-05。

**提示词权限的汇总解释：** 用户限制的是“日志中的全文”。素材/项目是业务复用面，授权运营可看/复制业务提示词，普通日志仍不返回全文。若希望所有入口都只有管理员能见，需按 Q-01 调整；不得靠复制接口绕过最终权限规则。

### 8.4 模型价格录入与 AI 查价（末轮补充确认）

四种价格必须区分：**官方公开标价、当前渠道价格、平台结算价、供应商实际账单**。管理员可同时查看官方/渠道候选，最终自行确定平台结算价；官方数字不直接等于渠道扣款，也不自动成为商家收费标准。

1. 手动定价：模型 × 能力/操作 × 档位，录入原币金额、计价单位、倍率、平台金额、生效时间。
2. AI 查价：管理员主动发起，固定查价服务访问允许的官方/渠道公开来源，返回模型版本、档位条件、原币价格、单位、页面标题、来源链接、抓取时间和匹配说明。
3. 候选确认：未确认只保存草稿；管理员核对版本、地区、档位和币种后选用，记录操作者、依据和生效版本。**无论 AI 置信度多高，均不得自动生效。**
4. 新任务估价使用当前有效档位，任务保留完整价格快照；重查/改价不改变已提交任务。原币折算必须保存汇率、来源、日期，不静默换汇或默认税费为零。
5. 失败、无公开价格、版本不匹配或价格过期：说明原因，保留手动定价入口；过期提示复核，不自动覆写历史价格。有效平台价格与待确认候选分别显示。

基础单位包括每张、每秒/分钟、每次调用、每千/百万输入与输出 token、每千字符。文本输入输出单价分开，图片至少按尺寸/质量区分；视频、语音价格字段可登记，但**不代表执行器已接入**。缓存、批量和复杂阶梯价后续，不用一个均价冒充所有规格。

查价不能依赖正在被定价的模型自行上网：要有独立的搜索/浏览与提取能力、可核实来源及限额；普通文本模型不被假定拥有联网能力。页面内容只作价格数据，不执行其中指令；不得访问内网、回环、云元数据或绕过登录。查价费用和来源配置见 Q-10。查价、采用、改价与失效全部入审计。

| 问题 | 统一处理 | 性质 |

| AI 官方价 vs 最终收费 | 官方/渠道仅参考候选；管理员确认平台结算价，按档位和快照计费 | 用户末轮明确确认 |

| 模板文字最终合成 vs 整图润色 | 默认无字底图后合成；整图润色是高风险分支，重做文字/保真检查 | 澄清生产稿绝对表述 |
| 失败不收费 vs 供应商可能收费 | 内部不按成功结算，供应商成本单独核对 | 分开成本与客户账本 |

| 语音/视频目录 vs 系统稿试听验收 | 本轮只验目录与执行拒绝；试听/视频下载留后续 | 已确认阶段边界 |
| 模板图层 vs 提示词模板 | 素材模板是提示词/示例；04 排版模板是内部合成结构，不开放 PSD 编辑 | 汇总术语 |

| 精修每次单独确认 vs 工作流自动串联 | 工作流内预置节点随整条一次确认；开跑后新增手动精修仍单独确认；不支持自动循环 | 用户 2026-10-21 确认 |
| 六步唯一路径 vs 画布自定义 | 同一项目两种视图，锁定节点保留审核/导出门禁；不是第二条生产路径 | 用户 2026-10-21 确认 |
| 工作流画布 vs NEXT-04 可编辑画布 | 前者是任务编排画布（本轮），后者是图像编辑画布（后续），概念分开 | 汇总术语 |
| `workspace_id=local` vs 多账号 | 业务统一真实工作空间 ID；旧素材 SQL 仅示意，不可直接照抄上线 | 汇总数据约定 |

| 费用日志 | `sj_model_prices / sj_price_lookups / sj_billing_ledger / sj_audit_logs` | 价格档位与版本、AI 候选及来源、管理员确认、高精度快照、不可覆盖流水、幂等与审计 |

项目资料快照与商品版本是不同对象：前者冻结一次交付的选择和约束，后者记录商品事实历史。不能只存一个可变商品 ID 充当快照。

### 10.2 接口分组

| 分组 | 草案入口 | 必要约束 |
| --- | --- | --- |
| 会话用户 | `/api/session`、`/api/setup/admin`、`/api/users`、`/api/account/password` | 初始化受控、角色与 CSRF、停用失效 |
| 商品 | `/api/products`、`/:id/versions`、`/api/product-imports`、`/api/uploads` | 来源分类、指纹去重、导入状态、版本冲突校验 |
| 项目 | `/api/projects`、`/:id/plans`、`/:id/batches`、交付项/版本/审核/导出子资源 | 审核门禁、显式快照、命令幂等，不信任客户端状态 |
| 工作流 | `/api/projects/:id/plans/:v/planning`、`/api/task-types`、`/api/workflow-templates`、交付项 `/workflow`、`/workflow/estimate`、`/workflow/runs` | DAG 与端口校验、锁定节点不可改、乐观锁、估价与开跑幂等 |
| 素材 | `/api/assets`、`/:id`、`/:id/file`、`/:id/thumb`、`/api/asset-templates` | 游标分页、同源文件、按权限返回提示词 |

| 账单日志 | `/api/billing/*`、`/api/model-prices`、`/api/audit-logs`、`/api/model-calls`、`/api/job-events` | 幂等分录、脱敏、筛选分页、导出权限 |
| 查价与采用 | `/api/models/:uid/price-lookup`、`/:uid/price-lookups`、`/api/model-prices/:uid/:operation/apply-lookup` | 管理员主动发起/采用，来源可验证、候选不直接生效；价格表按档位维护 |

接口路径是汇总草案；开发可调整命名，必须更新契约，不能改变本稿业务语义。统一错误需至少区分：未登录、无权限、版本冲突、重复参数冲突、模型未配置/不可执行、额度不足、来源过期、解析失败/部分成功、上游未知、结果不可用。

### 10.3 技术与安全底线

- 复用 PostgreSQL、Redis、MinIO；Redis 键/频道 `sj:`，若采用 BullMQ 则 `sj:bullmq`。当前已有 PostgreSQL 执行队列，不为文档统一强制迁移队列技术。
- 只用私有桶 `shangjing-assets / shangjing-exports`，模型输入须通过已验证上传协议或公共信任网关；不关闭 TLS 校验、不把服务密钥给浏览器。
- 文件上传验证格式、解码、尺寸与大小；用户 SVG/可执行内容不得按可执行页面提供。网页抓取逐跳验证外部目标，防止内网、回环、元数据和重定向绕过。
- 页面/截图/模型输出均视为数据而非指令，渲染转义；AI 结构化输出须 schema 校验，不能直接当数据库命令。
- 同步与异步任务都须限制耗时/输出/并发；不能仅因网络超时就产生新付费请求。
- 编辑使用版本号等乐观锁；余额使用事务与行锁，账单/任务幂等由数据库唯一约束兜底。
- 大列表分页、缩略图、懒加载；桌面与手机核心流程可用，键盘可操作，加载/空/部分成功/失败/权限不足状态明确。
- 文档不承诺“8–12 分钟生成完毕”或固定成本；实际耗时和价格由运行数据与管理员配置决定。

| ACC-12 | 素材模板复用 | 原图下载正确，源图过期说明；模板带入项目后仍待确认，无自动生成/扣费 |
| ACC-13 | 账本 | 有价成功扣一次、明确失败释放、未知待核；未定价放行后补价一次；文本辅助只记成本 |
| ACC-14 | 模型中心 | 能力标记、别名、默认换浏览器一致；未接执行器明确拒绝；不自动付费回退 |
| ACC-15 | 日志与数据 | 日志提示词仅管理员；无密钥/令牌/连接串；历史任务/文件仍可追溯，旧数据不补造金额 |
| ACC-16 | 产品一致性 | 工作台与账本同源；移动端可用；模拟状态不冒充真实能力；本轮不出现可点击的假视频按钮 |
| ACC-17 | AI 查价与价格档位 | 官方/渠道候选有链接、时间、版本/档位和原币；无来源不能采用，未确认不参与估价；管理员选定平台价后仅影响新任务；文本输入输出和图片尺寸/质量分别计价 |

| ACC-18 | AI 规划 | 输入补充要求后得到类型库内的待确认清单；扩展建议需采纳；未在资料中的事实不进正式提示词；文本模型不可用回退默认清单；规划只记成本 |
| ACC-19 | 工作流编辑 | 交付项从模板复制实例；改实例不影响模板；锁定节点不可删/绕过；回边与不兼容端口被拒；另存模板可在新交付项选用 |
| ACC-20 | 工作流执行 | 逐节点估价并一次确认；自动串联；某节点失败只停该分支并释放下游预占，不自动重试；未知保持等待；运行中改未执行节点需重新确认 |
| ACC-21 | 双视图一致 | 六步与画布显示相同状态和版本；并行分支各自成版本，候选需显式选定；两视图并发保存冲突有提示 |
| ACC-22 | 方案版本化 | 确认后重新规划生成新方案版本；旧交付项、版本和费用保留；未改动交付项不重复计费 |

自动测试用模拟供应商与隔离数据；真实付费能力验收单独说明次数、用途和费用后执行。完成一个阶段必须更新“实际状态”，附测试证据，不能只把需求状态改成“已完成”。

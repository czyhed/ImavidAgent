# 画布 / 视频工作台保存与同步重做（2026-10-27 确认）

## 背景（现状问题）

- 画布页常驻 2.5 秒轮询整份项目详情，无任务运行时也不停。
- 平移 / 缩放结束写 `viewport`，触发整项目 PATCH；每次保存提交整份 tasks / edges。
- 整项目 `revision` 锁：服务端 27 处写入递增版本（执行、配音、AI 分镜、批量推进等），本地有未保存改动时即弹「项目已在其他窗口更新 / 载入服务器版本」并锁住编辑。
- 视频工作台「保存分镜」走独立 storyboard PATCH，也带版本，与画布互相顶掉。

## 已确认决定

| 编号 | 决定 |
| --- | --- |
| S1 | 取消整项目版本锁。保存只提交变化：节点字段、节点增删、连线增删、任务分组、项目名、角色、分镜。服务端按节点合并；不同节点互不影响；同一字段后写为准，不弹冲突。 |
| S2 | 改了才保存，合并提交：最后一次改动后约 1 秒发送，连续改动最长 5 秒必发；失焦、切走标签页、离开页面时立即发送。同时只有一个保存请求在途。顶部显示「已保存 / 未保存 / 保存中 / 保存失败·重试」。画布视角只存本机浏览器，不再写服务器。 |
| S3 | 取消常驻轮询。无运行中任务（生成、批量、配音、合成）时不发请求；有时每 3 秒查轻量状态接口，结束即停。打开页面、标签页切回时各刷新一次。 |
| S4 | 系统写入（运行结果、配音音频、尾帧、AI 建议状态、批量进度、成片）与用户编辑分开，不覆盖用户正在编辑的字段，不触发冲突；系统写入不递增「内容版本」。 |
| S5 | 删除「载入服务器版本」横幅，编辑永不锁定。网络 / 5xx 失败保留本地改动，自动重试 3 次（约 1 / 3 / 9 秒），之后显示「重试」。校验类错误（4xx）显示原因，丢弃该批改动并以服务端状态为准，保留其后的本地改动。撤销 / 重做只在本地，产生的结果同样走增量保存。 |
| S6 | 视频工作台与画布共用同一保存队列与增量协议，去掉「保存分镜」按钮与分镜版本要求。 |
| S7 | 先交付保存与同步重做（画布、工作台一起），部署后再在新机制上做视频工作台界面重做（时间线 + 单镜编辑、工作台内直接加素材、项目级参数、抽屉、连续预览、问题标记、移动端可编辑）。 |

## 实现约定

- 新接口 `POST /api/creation/projects/:id/ops`：`{ ops: [...] }`，在项目咨询锁内一次事务应用，复用现有校验（图校验、运行中节点禁止改执行输入、有历史节点禁止删除、引用校验）。引用已被其他窗口删除的节点的操作跳过并在响应 `skipped` 中列出。返回项目详情。
- 操作类型：`task.add`、`task.patch {id, fields}`、`task.remove`、`edge.add`、`edge.remove`、`workflow.put`、`workflow.remove`、`project.patch {name?, voiceRoles?}`、`storyboard.patch {script?, shots?}`（复用现有分镜应用逻辑）。客户端由前后快照比对生成操作，界面编辑接口不变。
- `GET /api/creation/projects/:id/status`：只返回 `revision`、runs、dubStates、分镜 batch / compile 状态。`revision` 变化（他处编辑）时客户端再取一次详情，把未发送的本地改动重新叠加在服务端状态上。
- 执行预览 / 开始不再比较整项目版本，改为比较所选节点冻结输入的哈希；不一致时自动重新预览并提示，不锁定。配音、尾帧、批量、AI 分镜等动作不再要求 revision，调用前先清空保存队列。
- 旧整项目 PATCH 与 storyboard PATCH 保留兼容，前端不再使用。
- 画布视角键 `sj:canvas-view:<projectId>:<workflowId>`，读写均 try/catch。

## 实现记录与偏离（2026-10-27）

以下是实现与上文约定的差异及原因；其余条目按原文实现。

- **401 / 403 不丢弃改动。** S5 只规定 4xx 校验类错误丢弃该批。登录过期或无权限同样是 4xx，但丢弃会让用户的编辑悄悄消失，所以这两类按「保存失败 · 重试」处理：保留改动、不自动重试，登录恢复后点「重试」。其余 4xx（含 408 / 429 以外）仍丢弃并以服务端状态为准；408 / 429 与网络 / 5xx 一并按可重试处理。
- **分镜表按整表后写为准。** `storyboard.patch` 的 `shots` 是整张分镜表（顺序、标题、描述、节点编号），不是逐镜合并。两个窗口同时增删分镜时，后到的一批覆盖前一批的分镜表；节点字段（提示词、时长、素材等）仍按节点合并，不受影响。服务端对「没带 nodeId、但编号已存在」的分镜沿用已建节点，因此响应丢失后重发不会重复建节点。
- **轻量状态里的运行记录不含冻结输入。** `GET /status` 的 `runs[].input` 只有 `{kind}`，避免每 3 秒下发整份冻结输入。客户端在以下情形再取一次完整详情：修订号变化、出现未知运行编号、某运行从进行中变为终态（刷新费用与结果）、配音状态与已知不一致。
- **预览令牌改为所选节点的冻结输入哈希。** 令牌不再含整项目修订号；`scope` 内每项带该节点的输入哈希（含入边来源）、解析后的提示词 / 素材 / 模型。批量预览同理（每镜 `inputHash`）。令牌不一致时开始返回 `PREVIEW_CHANGED`，前端自动重新预览并提示。无关节点的增删不会让预览失效。
- **系统写入不递增修订号，但其他窗口不一定立即看见。** 尾帧截取、配音音频只改节点上的服务端字段且不递增修订号；其他窗口在下一次「打开 / 标签页切回 / 有运行中任务时配音状态变化」时才会取到。本窗口的动作响应直接带回最新详情，不受影响。
- **用户可见的内容变更仍递增修订号：** 用户编辑（ops 与旧 PATCH）、同步商品资料、确认 AI 安排、确认 AI 分镜（新建节点）。
- **旧 PATCH 仍要求 `revision`。** 整项目 PATCH 与 storyboard PATCH 保持原样（含 `REVISION_CONFLICT`），仅前端不再调用；整项目 PATCH 仍接受 `viewport`。`ops` 不接受视角，`project.patch` 里带的 `viewport` 被忽略。
- **旧画布（无创作任务容器）首次增量保存时升级：** 与前端 `normalizeProject + withWorkflows` 一致（image→generate、补连线端口、补 `workflowId`），升级发生在 ops 事务内，只写一次。
- **全部跳过或没有实际变化的批次不写库**，不递增修订号（重发同一批、他处已删除节点的操作）。
- **`pagehide` 用 `fetch(..., {keepalive:true})`**，浏览器对 keepalive 请求体有约 64 KB 上限；超过时这一次尽力发送可能被拒，改动仍在本地队列，下次打开页面不会恢复（队列不落盘），属已接受的尽力而为。
